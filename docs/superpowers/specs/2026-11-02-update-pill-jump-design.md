# 패널 새 업데이트 표시: 점프 애니메이션 설계

## 의도

업데이트를 받아 두면(`status === 'ready'`) 패널 툴바에 "새 버전 x.y.z" 알약이 뜬다. 지금은 연한 초록 바탕에 움직임이 없어서 사용자가 잘 놓친다. 알약을 더 눈에 띄게 바꾸고 계속 움직이게 해서, 패널을 열자마자 업데이트가 있다는 걸 알아채게 한다.

## 목표 / 비목표

- 목표
  - 알약 바탕을 꽉 찬 초록으로 바꾼다.
  - 마우스를 올려 두지 않은 동안에는 점프 애니메이션이 계속 반복된다.
  - 마우스를 올리면 멈추고, 마우스가 벗어나면 다시 움직인다.
- 비목표
  - 업데이트 흐름(확인 팝오버, 설치, 재시작)과 표시 조건은 바꾸지 않는다.
  - 설정 창의 업데이트 행은 건드리지 않는다.
- 안티 목표
  - 툴바 레이아웃이 밀리는 것
  - 애니메이션이 패널 위쪽 가장자리에서 잘리는 것
  - "동작 줄이기"를 켠 사용자에게도 계속 움직이는 것

## 결정된 디자인 (시안 E)

- **알약 색:** `bg-ok-bg text-ok-fg`를 `bg-success text-success-content`로 바꾼다. 두 테마 모두 토큰이 이미 있다.
- **아이콘:** 맨 앞의 점(`<i>`)을 `↑` 화살표로 바꾼다. 장식 요소라 `aria-hidden`을 단다.
- **움직임:** 1.8초 주기로 반복한다. 주기의 앞 55%는 쉬고, 나머지 구간에서 아래 순서로 움직인다.
  1. 납작하게 웅크린다(scale 1.12 × 0.85).
  2. 위로 뛰어오르며 길쭉해진다.
  3. 떨어지면서 다시 찌그러진다.
  4. 제자리로 돌아온다.
- **그림자:** 알약 아래에 흐린 초록 타원 그림자를 두고, 점프와 같은 리듬으로 작아졌다 커지게 한다.
- **호버:** `hover:animate-none`을 알약과 그림자 모두에 적용한다.
- **동작 줄이기:** `prefers-reduced-motion` 블록에 `.animate-jump`를 추가한다. 이때는 꽉 찬 초록 알약만 보이고 움직이지 않는다.

## 구현 방법

- **채택:** `globals.css`의 `@theme`에 `--animate-jump`(알약)와 그림자용 토큰, 그리고 각각의 `@keyframes`를 추가한다. `Toolbar.tsx`는 클래스만 바꾼다.
- **기각:** 컴포넌트에 스타일을 직접 넣는 방식. 애니메이션은 `globals.css`에 둔다는 디자인 규칙에 어긋난다.
- **기각:** JS(Web Animations API)로 돌리는 방식. CSS로 충분해서 코드만 늘어난다.

## 제약

- 패널은 `overflow-hidden`이고 툴바 위 여백은 10px(`pt-2.5`)다. 그래서 점프 높이는 약 7px로 잡는다(목업은 9px). 실제 앱에서 잘리지 않는지 확인한다.
- `update` 클래스(`closest('.update')`가 읽는 DOM 훅)와 확인 팝오버 구조는 그대로 둔다.
- 색 값은 `globals.css` 토큰만 쓰고, 컴포넌트에 hex 값을 쓰지 않는다.

## 빌더에게 맡기는 것

- 키프레임의 세부 수치(scale, 높이)는 실제 앱에서 보면서 다듬는다.
- 그림자를 Tailwind `after:` 유틸리티로 만들지, 작은 `<span aria-hidden>`으로 만들지는 빌더가 정한다.
- 확인할 것
  - 라이트/다크 테마, 한국어/English
  - 사이드 도킹 상태(툴바 줄바꿈)
  - 패널은 agent-desktop으로 접근할 수 없으므로, 사용자에게 dev 앱 패널을 열어 달라고 요청한다.

# 에디터 배경 제거: 피사체 선택 + 브러시 설계

- 날짜: 2026-10-31
- 브랜치: `feature/editor-bg-brush-subject`
- 목업: `.superpowers/brainstorm/57117-1793456813/content/bg-tools-layout.html` (B안 채택)

## 1. 왜

지금 에디터의 「배경 제거」 탭은 BiRefNet으로 "가장 눈에 띄는 대상 하나"를 자동으로 남기는 원클릭 도구뿐이다. 사용자가 실제로 겪은 문제는 두 가지다.

1. 사진에 대상이 여러 개면, 자동이 사용자가 원한 대상이 아닌 것을 남긴다. **사용자가 남길 대상을 직접 고르고 싶다.**
2. 자동 결과에서 **피사체 일부가 지워지는** 경우가 있다. 지워진 부분을 되살리거나, 남은 배경을 손으로 지우고 싶다.

## 2. 목표 / 비목표 / 실패 조건

**목표**
- 배경 제거 탭에 도구 세 개: **자동**(BiRefNet, 지금 그대로), **피사체 선택**(SAM, 클릭으로 대상 고르기), **브러시**(지우기 / 복원, 모델 없음).
- 세 도구 모두 지금 편집 모델(`EditOp` 단계 목록, ⌘Z, 복사)에 그대로 올라간다.
- SAM은 BiRefNet과 **따로** 설정에서 받는다. 브러시는 모델 없이 언제나 쓸 수 있다.

**비목표**
- SAM으로 자동 제거를 대신하기. SAM은 프롬프트(클릭) 없이는 주인공을 고르지 못하고, 경계 품질도 BiRefNet보다 떨어진다. 둘 다 남긴다.
- 박스 프롬프트, 여러 대상을 자동으로 나눠 보여주기, 경계 매팅(머리카락 다듬기), GPU 실행.
- 브러시 경도·불투명도 조절, 다른 탭에서의 브러시.
- 배경 제거 탭 밖 UI(자르기·회전·크기·업스케일) 변경.

**실패 조건 (동작은 해도 실패로 본다)**
- 브러시를 긋는 동안 커서·획이 끊기거나 늦게 따라온다.
- ⌘Z 한 번에 무엇이 되돌아갈지 예측할 수 없다.
- 클릭할 때마다 SAM 인코더를 다시 돌려 수 초씩 기다린다.
- 새 Rust/JS 의존성이 생긴다(필요하면 먼저 사용자에게 묻는다 — CLAUDE.md).

## 3. 제약

- 편집은 `ops: EditOp[]`로 쌓이고, Rust `app/editor.rs::render`가 매번 원본부터 다시 그린다. AI 단계 결과는 `ai_key(session, ops[..=i])`로 캐시된다.
- 미확정 단계는 `pending` 하나다. 복사는 `[...ops, pending]`을 쓴다.
- 미리보기는 긴 변 2048px(`PREVIEW_SIDE`)로 줄인 PNG data URL이다. 좌표는 crop처럼 **그 단계가 적용되는 이미지의 풀해상도 px**로 보낸다.
- ONNX Runtime은 앱에 번들되어 있고 `ort`(rc.15, `load-dynamic`)로 쓴다. `ai.rs`의 `RUN` 전역 락으로 한 번에 하나씩 돈다.
- 모델 엔진은 `app/engines.rs`의 `SPECS`/`pinned()`. URL은 `SOURCES`의 rembg 릴리스 경로 아래여야 하고, SHA-256과 크기가 상수로 고정된다.
- 문자열은 `src/shared/i18n/{en,ko}.ts`, 색은 `globals.css` 토큰만. 라이트/다크, 한/영 확인.

## 4. 접근 방법 (검토한 것)

| | 방법 | 트레이드오프 |
|---|---|---|
| **1 (채택)** | SAM(포인트 프롬프트) 모델을 새 엔진으로 추가 | 원하는 대상을 정확히 고른다. 대신 받을 모델이 하나 더 생긴다. 인프라(다운로드·ORT)는 그대로 재사용한다. |
| 2 | BiRefNet 마스크를 연결 영역으로 나눠 클릭으로 고르기 | 가볍지만, 자동이 원하는 대상을 이미 지웠거나 대상끼리 붙어 있으면 못 고른다. 사용자의 실제 문제를 못 푼다. |
| 3 | 브러시만 먼저 | 가장 작지만 요청의 절반이다. |

사용자는 1을 골랐다. 문제의 원인이 "자동 결과가 틀린다"이므로, 자동 결과에 기대는 2로는 해결되지 않는다.

UI 배치는 목업 A(하단 모드 전환) / **B(왼쪽 도구 막대)** / C(두 단계 흐름) 중 **사용자가 B를 골랐다**.

## 5. 정해진 것

### 5.1 화면 (B안)

- 배경 제거 탭일 때만, 무대(stage) 왼쪽 가장자리에 세로 **유리 도구 막대**(`.glass`)를 띄운다. 버튼 세 개: 자동 / 피사체 선택 / 브러시. 아이콘 전용 버튼이므로 `aria-label`과 툴팁을 단다. 역할은 `radiogroup`/`radio`. 기본 선택은 **자동**이다.
- 하단 막대(지금 `h-16` 영역)에는 고른 도구의 옵션과 「적용」만 보인다.
  - 자동: 지금과 같다(힌트 + 적용/다시 시도). 모델이 없으면 `ModelPrompt`.
  - 피사체 선택: 힌트 "남길 대상을 클릭하세요 · ⌥클릭으로 빼기"(Windows는 Alt) + 「초기화」 + 「적용」. SAM이 없으면 SAM용 `ModelPrompt`.
  - 브러시: `Segmented` 「지우기 / 복원」 + 크기 슬라이더 + 「적용」.
- 이미지는 막대에 가리지 않도록 무대 폭을 막대만큼 줄여 맞춘다. 막대가 이미지 위에 겹쳐도 되는지는 빌더가 정한다(5.6).

- **도구 전환 규칙 (사용자 결정):** 피사체 선택 점이나 브러시 획이 pending에 있는 채로 다른 도구(또는 다른 탭)로 가면, 그 pending을 **자동으로 적용**한다(`ops`에 한 단계로 들어가고 ⌘Z 한 번에 되돌아간다). 자동 도구의 결과는 미리보기일 뿐이므로, 「적용」을 누르지 않았으면 **버린다**. 자동이 기본 도구라서 둘러보기만 해도 배경이 지워지면 안 되기 때문이다.

### 5.2 자동

지금 동작 그대로다(`removeBg` 단계, 비교 보기, 적용).

### 5.3 피사체 선택 (SAM)

- 새 단계: `{ type: 'subject', points: { x: number; y: number; keep: boolean }[] }`. 좌표는 정수이고, 그 단계 직전 이미지의 풀해상도 px다. Rust `Op::Subject { points: Vec<SubjectPoint> }`이고, serde 모양을 맞춘다.
- 클릭하면 `keep: true`, ⌥/Alt+클릭하면 `keep: false` 점이 pending 단계에 추가된다. 클릭할 때마다 `renderEdit([...ops, pending])`을 다시 부른다. 「초기화」는 점을 모두 비운다(pending = null).
- **인코더는 이미지당 한 번만 돈다.** SAM 이미지 임베딩을 세션에 `ai_key(session, ops[..i])`(subject 단계 **앞까지**)로 캐시하고, 클릭마다 디코더만 돌린다. 결과 이미지 캐시는 지금처럼 `ops[..=i]` 키다.
- 결과: 디코더 마스크(가장 점수 높은 것)를 이미지 크기로 키워 알파로 쓴다. 기존 `apply_mask`와 같은 방식이고, **RGB는 건드리지 않는다**(5.4의 복원이 여기에 기댄다).
- **알파는 덮어쓴다 (사용자 결정).** 앞에 자동이나 브러시를 적용했더라도, 고른 대상 기준으로 처음부터 다시 따낸다. 그래서 자동이 잘못 지운 부분도 피사체 선택으로 바로잡을 수 있다. 피사체 선택은 "자동 대신 쓰는 도구"이고, 힌트 문구도 그렇게 쓴다. 원본이 처음부터 투명하던 곳을 고르면 그 아래 RGB가 보이는데, 이 경우는 받아들인다(5.4와 같다).
- [작성자 판단] 좌표는 정수 px(`u32`)로 보낸다. 그래야 `Op`가 `Eq`/`Hash`를 유지해 캐시 키로 쓸 수 있다. 브러시 좌표와 반지름도 같다.
- 표시: 미리보기 위에 결과를 겹친다. 고른 영역은 그대로, 나머지는 어둡게(원본을 낮은 불투명도로 깔고 결과를 위에) 보여 준다. 각 점은 초록 ＋ / 빨강 − 원으로 찍는다. 첫 클릭에서 인코더가 도는 동안에는 지금의 AI 스피너를 쓴다.
- 「적용」하면 pending이 `ops`로 들어간다(⌘Z 한 번에 통째로 되돌아간다). 적용 전 ⌘Z는 **마지막 점 하나**를 뺀다.

### 5.4 브러시

- 새 단계: `{ type: 'brush', strokes: { mode: 'erase' | 'restore'; radius: number; points: [number, number][] }[] }`. 좌표와 반지름은 풀해상도 px다.
- Rust는 각 획을 순서대로 알파에 그린다. `erase`는 알파를 0 쪽으로, `restore`는 255 쪽으로 보낸다. 가장자리는 부드럽게(고정 페더) 처리하고, 점 사이는 선분으로 채운다. RGB는 건드리지 않는다.
  - **불변식:** 배경 제거류 단계(`removeBg`, `subject`, `brush`)는 알파만 바꾼다. 그래서 복원은 "배경 제거 전 픽셀"을 되살린다.
  - 원본이 처음부터 투명하던 곳을 복원하면 원본 RGB가 보인다. 이 경우는 받아들인다.
- 그리는 동안에는 프론트가 캔버스에 획을 반투명 보라(복원은 다른 토큰 색)로 바로 그린다(지연 0). **포인터를 떼면** pending 브러시 단계에 획을 추가하고 `renderEdit`으로 실제 결과를 받아 교체한다. 브러시는 AI 단계가 아니므로 캐시 없이 `apply_geometric` 쪽(이름은 빌더가 정리)에서 바로 계산한다.
- 크기: 슬라이더와 `[` / `]` 키. 반지름은 **화면 px로 고정**하고, 보낼 때 이미지 px로 환산한다. 커서는 크기를 보여 주는 원이다(흰선 + 어두운 점선이라 어느 배경에서도 보인다).
- 적용 전 ⌘Z는 마지막 획을 빼고, 적용 후에는 단계 하나를 되돌린다(5.3과 같은 규칙).
- 획이 많아져도 IPC가 무겁지 않도록, 프론트에서 반지름의 1/4보다 가까운 점은 버린다.

### 5.5 모델 엔진

- 새 `EngineId::Sam`(serde `"sam"`). 설정 > 변환의 엔진 목록에 BiRefNet 다음으로 `EngineSection engine="sam"`을 추가하고, 받기·업데이트·삭제를 따로 한다.
- `SPECS`의 binaries는 `["encoder.onnx", "decoder.onnx"]` 두 파일이다. 둘 다 raw 자산이고 고정 URL·SHA-256·크기를 쓴다. `ai.rs::model_path`는 지금 파일 하나만 받으므로, 두 파일을 받도록 넓힌다.
- 파일은 rembg `v0.0.0` 릴리스에서 받는다(2026-10-31 확인).

  | 후보 | 인코더 | 디코더 | 합계 |
  |---|---|---|---|
  | **MobileSAM (우선)** | `mobile_sam.encoder.onnx` 28.2MB | `sam_vit_h_4b8939.decoder.onnx` 16.5MB *(짝 확인 필요)* | 약 45MB |
  | SAM vit_b 양자화 | `vit_b-encoder-quant.onnx` 99.8MB | `vit_b-decoder-quant.onnx` 8.7MB | 약 109MB |

  MobileSAM이 rembg에서 실제로 어떤 디코더와 짝을 이루는지는 **빌더가 rembg 소스로 확인**한다. 그다음 `#[ignore]` 실모델 테스트(BiRefNet의 `installs_pinned_bgremove`와 같은 형태)로 두 후보 결과를 눈으로 비교해 하나를 고정한다. 품질이 비슷하면 작은 쪽을 쓴다.
- **확정 (계획 단계, 2026-10-31):** rembg `sessions/sam.py`는 `sam_vit_*` 인코더·디코더 쌍만 쓰고 MobileSAM은 짝짓지 않는다. 그래서 **SAM vit_b 양자화(약 117MB)**로 고정한다. MD5가 rembg `SAM_CHECKSUMS`와 일치한다.
- `remove_engine("sam")`도 `ai::forget`처럼, SAM이 도는 중이면 거부한다.

### 5.6 빌더에게 맡기는 것

- SAM 전처리·후처리 세부(긴 변 1024 리사이즈, 패딩, 좌표 변환, `orig_im_size` 입력)는 rembg `sam` 세션 구현을 따른다.
- 페더 폭, 슬라이더 범위·기본값, 도구 막대 아이콘 모양과 정확한 위치, 오버레이 색 토큰 이름.
- 세션 캐시에 임베딩을 얼마나 오래 두는지. 지금 캐시처럼 열기·닫기 때 비우면 된다.
- `sizeAfter`(`src/utils/edit.ts`)와 Rust 쪽 크기 계산에서 `subject`/`brush`는 크기를 바꾸지 않는다.

## 6. 테스트

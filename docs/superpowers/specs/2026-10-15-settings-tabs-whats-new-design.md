# 설정 탭 · 호버 선택 · 텍스트 드래그 · 복사 디바운스 · 새 소식 창 설계

- 날짜: 2026-10-15
- 브랜치: `feature/settings-tabs-whats-new`
- 디자인 기준: `docs/design/kraken-design.md`, 토큰은 `src/theme.css`
- 목업: `.superpowers/brainstorm/93751-1792066208/content/settings-tabs.html` (설정 **C안**), `whats-new-v2.html` (새 소식 **A안**)
- 버전: 0.7.1 → 0.8.0 (minor, 기능 추가) — 제 판단

## 왜

- 설정 항목이 한 화면에 길게 늘어서 있어 찾기 어렵다 → 성격별 탭으로 나눈다.
- 카드에 마우스를 올리고 `Enter`만 누르면 복사되게 해서 더 빨리 쓰고 싶다.
- 텍스트 카드를 다른 앱 입력란에 끌어다 놓고 싶다(지금은 파일·이미지 카드만 끌 수 있다).
- 터미널에서 드래그로 선택하면 선택이 바뀔 때마다 클립보드가 바뀌어 중간 상태가 카드로 잔뜩 쌓인다.
- 업데이트 뒤 무엇이 바뀌었는지 알려 주고 싶다.

## 공통 원칙

- 새 npm/cargo 의존성 없음(벤더링한 `drag` 크레이트 수정은 허용).
- macOS·Windows 모두 동작해야 한다.
- 새 UI 문자열은 `src/i18n/ko.ts`, `src/i18n/en.ts` 둘 다에 넣는다. 단, 새 소식 본문은 릴리스 본문 그대로(한국어만)다.

## 범위 밖 (하지 않음)

- 원클릭 복사 설정. 논의했다가 사용자가 빼기로 했다. 복사는 지금처럼 더블클릭·`Enter`.
- 새 소식 본문의 영어 번역.
- 텍스트 드롭 시 클립보드에 쓰기.

## 1. 설정 화면 탭 (C안: macOS 환경설정 툴바)

파일: `src/settings/Settings.tsx`, `src/settings/HistorySection.tsx`, `src/settings/settings.css`, i18n

- 창 맨 위(타이틀바 아래)에 아이콘+라벨 탭 4개를 가운데 정렬한다. 선택된 탭은 `--accent-subtle` 배경과 `--accent` 글자색, 10px 라운드. 목업 `settings-tabs.html` C안 참고.
- 기존 `<h1>설정</h1>`은 없앤다. 탭이 그 역할을 한다.
- 창 크기(520×600)는 그대로 둔다.
- 그룹 (사용자가 목업에서 보고 이의 없음):
  - **일반**: 테마, 언어, 로그인 시 자동 실행, 업데이트
  - **패널**: 복사할 때 소리 재생, 효과음, 개별 삭제 시 확인, 패널 크기 조절, 패널 크기 초기화
  - **단축키**: 단축키(패널 열기), 패널 고정 단축키
  - **기록**: 보관 기간, 기록하지 않을 앱, 전체 디스크 접근(macOS만, 지금처럼 조건부), 저장 통계·전체 삭제 — 지금 `HistorySection`의 내용
- 탭 상태는 기억하지 않는다. 창을 열 때마다 "일반" — 제 판단.
- 아이콘은 이모지/유니코드 기호나 인라인 SVG. 라이브러리 추가 금지. 구체 모양은 빌더 판단.
- 탭은 `role="tablist"`/`role="tab"`/`aria-selected`, 내용은 `role="tabpanel"`. 좌우 화살표로 탭 이동은 있으면 좋음(빌더 판단).
- 에러 문구(`.error`)와 `ConfirmModal`은 탭과 무관하게 지금처럼 동작해야 한다.

## 2. 패널 카드 호버 선택

파일: `src/panel/Card.tsx`, `src/panel/Panel.tsx`

- 마우스를 **실제로 움직여** 카드 위에 올리면 그 카드가 선택된다. 이후 `Enter`/`Shift+Enter`/`Cmd+P` 등 기존 키 동작이 그 카드에 적용된다.
- 다음 경우에는 선택이 바뀌면 안 된다(커서는 가만히 있고 카드가 커서 밑으로 지나가는 경우):
  - `←` `→`로 이동해 목록이 스크롤될 때
  - 마우스 휠로 스크롤할 때
  - 패널이 열리는 순간(최신 카드 선택 규칙 유지), 새 카드가 들어와 카드가 밀릴 때
  - 구현 힌트: `mouseenter` 대신 `mousemove`(실제 좌표 변화 확인)에서 선택. 방법은 빌더 판단.
- 카드 밖으로 마우스가 나가도 선택은 유지된다.
- 호버 선택은 클릭 선택과 부수효과가 다르다 — 제 판단:
  - 목록을 스크롤하지 않는다(가장자리에 반쯤 보이는 카드에 올려도 `scrollIntoView` 안 함). 키보드·클릭 선택은 지금처럼 스크롤.
  - 삭제 확인 중(`confirmingId`)인 카드의 확인을 취소하지 않는다.
  - 끝 근처 카드 선택 시의 `loadMore`는 그대로 둬도 된다(빌더 판단).
- 드래그 중(카드를 끌고 있는 동안)에는 호버 선택하지 않는다.
- 설정으로 끄는 옵션은 없다. 항상 켜짐 — 제 판단.

## 3. 텍스트·링크 카드 드래그 앤 드롭

파일: `src/panel/Card.tsx`, `src/panel/Panel.tsx`, `src-tauri/src/windows.rs`(`start_drag`), `src-tauri/vendor/drag/src/platform_impl/windows/mod.rs`

- 지금 파일·이미지 카드에만 있는 드래그(카드가 떠올라 커서를 따라가고, 패널 밖으로 나가면 OS 드래그 시작, 드래그 이미지는 카드 모양)를 텍스트·링크 카드에도 똑같이 적용한다.
- 다른 앱(텍스트 편집기, 브라우저 입력란 등)에 놓으면 **놓은 자리에 텍스트가 바로 들어간다**. 사용자 확인 사항.
- 클립보드는 건드리지 않는다. 놓은 뒤 처리는 지금 파일·이미지 드롭(`finish_drag` → `confirm_copy`)과 **똑같다**: 카드를 맨 앞으로(`lastUsedAt` 갱신), 효과음, "복사됨" 알림, 패널 고정이 아니면 패널 숨김. 종류별 분기를 만들지 않는다 — 제 판단(파일 드롭도 클립보드를 안 건드리면서 같은 알림을 쓰므로 일관성). 패널 안에 놓으면 지금처럼 제자리로 돌아간다.
- 드래그로 넘기는 내용은 일반 텍스트(서식 없는 텍스트). 링크 카드는 URL 텍스트. 리치 텍스트·URL 타입 추가 여부는 빌더 판단.
- 플랫폼:
  - macOS: `drag` 크레이트의 `DragItem::Data { provider, types }`로 `public.utf8-plain-text`를 제공한다(이미 지원).
  - Windows: 벤더링한 `drag`의 `DragItem::Data`는 지금 지원하지 않는다(`platform_impl/windows/mod.rs` 268행 부근). `CF_UNICODETEXT`를 담은 `IDataObject`로 텍스트 드래그를 구현한다. 기존 벤더 수정(드래그 이미지 중심 잡기)과 같은 방식으로 변경 사항을 `Cargo.toml` 주석에 남긴다.
- 전체 디스크 접근은 파일 드래그에만 해당한다. 텍스트 드래그에는 필요 없다.

## 4. 복사 디바운스 (0.5초)

파일: `src-tauri/src/watcher.rs`

- 클립보드 변화를 받으면 바로 기록하지 않는다. **마지막 변화 뒤 0.5초 동안 더 바뀌지 않으면** 그때의 클립보드 내용 하나만 기록한다(trailing debounce).
- macOS 폴링 주기: clipboard-rs 기본 500ms는 디바운스(500ms)와 같아서, 드래그 중 변화가 ~500ms 간격으로 들어오면 타이머가 그 사이에 터져 중간 상태가 기록될 수 있다. 그래서 `ClipboardWatcherContext::new_with_interval`로 macOS 폴링을 **200ms**로 줄인다. changeCount 비교만 하므로 CPU 부담은 미미하다 — 제 판단. 0.5초 디바운스는 사용자 요청대로 유지.
- 결과: 터미널 드래그 선택처럼 연속으로 바뀌는 경우 마지막 내용 하나만 남는다.
- 알고 받아들인 결과:
  - 0.5초 안에 서로 다른 두 내용을 연달아 복사하면 마지막 것만 남는다.
  - 카드가 패널에 나타나기까지 약 0.5~0.7초 늦어진다.
- 기존 동작 유지:
  - Vee 자신이 쓴 클립보드 무시(`watcher_suppressed`, 1200ms. `lib.rs`의 주석·테스트가 500ms 폴링을 전제로 하므로 함께 고친다). 디바운스로 기록 시점이 늦어져도 자기 쓰기가 기록되면 안 된다. 억제 판정을 변화 감지 시점에 할지 기록 시점에 할지, 억제 창(1200ms)을 늘려야 하는지 빌더가 확인하고 테스트로 고정한다.
  - 암호 관리자 숨김 타입(`CONCEALED_FORMATS`) 무시, 기록하지 않을 앱 무시.
  - 원본 앱(`source_app`)은 기록 시점에 판정해도 된다(0.5초 사이 앱 전환은 드묾) — 제 판단. 변화 감지 시점의 앱을 쓰는 게 쉽다면 그쪽이 더 정확하다.
- 0.5초는 상수로 둔다. 설정 항목 없음.

## 5. 업데이트 후 "새 소식" 창 (A안)

### 글의 출처: GitHub 릴리스 본문 그대로

- `scripts/latest-json.mjs`가 `latest.json`을 만들 때 `gh release view <tag> --json body`로 릴리스 본문을 읽어 `notes` 필드에 넣는다(Tauri 업데이터 표준 필드). `buildManifest`에 인자를 추가하고 `latest-json.test.mjs`에 테스트 추가.
- 앱은 업데이트를 내려받을 때(`updater.rs` `check` → `Ready`) `update.body`와 `update.version`을 설정 저장소에 저장한다. 예: `pendingNotes`(본문), `pendingNotesVersion`(버전). 키 이름은 빌더 판단.
- 이번 릴리스(0.8.0)로 올리는 사용자는 아직 이 기능이 없는 0.7.1에서 내려받으므로 저장된 본문이 없다 → 0.8.0으로 갈 때는 창이 뜨지 않는다. 다음 릴리스부터 동작한다. 받아들임 — 제 판단.

### 언제 띄우나

- 앱 시작 시 저장된 `pendingNotesVersion`이 현재 앱 버전과 같으면 창을 띄우고, 띄운 뒤 두 키를 지운다(한 번만).
- 같지 않으면(설치 실패 등으로 버전이 다름) 띄우지 않고 그대로 둔다. 버전이 현재보다 낮으면 지운다 — 세부는 빌더 판단.
- 처음 설치, dmg/exe로 직접 설치한 경우: 저장된 본문이 없으므로 띄우지 않는다. 사용자 확인 사항.
- 여러 버전을 건너뛰면 마지막(설치된) 버전의 본문만 보인다.

### 창 모양 (목업 `whats-new-v2.html` A안)

- 새 webview 창 라벨 `whats-new`. `tauri.conf.json`에 `create: false`/`visible: false`로 정의하거나 런타임 생성 — 빌더 판단. 화면 가운데, 약 400×480, 크기 조절 불가, 다른 창처럼 테마 따름. `src/main.tsx`의 라벨 분기에 추가.
- 구성: 버전 배지(`--ok-bg`/`--ok-fg`, 6px 라운드) → 제목 "새로워진 Vee"(en: "What's new in Vee") → 본문 → 오른쪽 아래 보라색 "확인" 버튼(12px 라운드). 본문이 길면 본문 영역만 스크롤.
- 본문 렌더링: 릴리스 본문 마크다운을 **그대로** 보여준다. 지금 릴리스 본문이 쓰는 문법 — `##`/`###` 제목, `-` 목록과 들여쓴 하위 목록, `**굵게**`, `` `코드` `` — 를 렌더링한다. `` `⌘⇧P` `` 같은 코드는 키캡 모양이면 좋다(빌더 판단). 그 밖의 문법은 일반 텍스트로 보여도 된다. 라이브러리 추가 없이 작은 렌더러로 구현하고, HTML은 해석하지 않는다(XSS 방지: `dangerouslySetInnerHTML` 금지, React 요소로 만든다).
- "확인", 창 닫기, `Esc`, `Enter` 모두 창을 닫는다(숨김).
- 앱이 메뉴바 앱(Accessory)이므로 창을 띄울 때 포커스를 줘서 앞에 보이게 한다.

### 릴리스 절차 변경

- `docs/release.md`: "`latest-json.mjs`를 돌리기 전에 릴리스 본문을 완성해 둘 것. 본문이 그대로 앱의 새 소식 창에 나온다."를 추가.

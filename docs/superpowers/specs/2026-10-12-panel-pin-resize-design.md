# 패널 고정 · 패널 크기 조절 · 버그 2건 설계

- 날짜: 2026-10-12
- 브랜치: `feature/panel-pin-resize`
- 디자인 기준: `docs/design/kraken-design.md`, 토큰은 `src/theme.css`
- 목업: `.superpowers/brainstorm/46658-1791799674/content/panel-pin-resize.html` (패널 **C안**, 설정 **S2안** 선택)
- 버전: 0.6.3 → 0.7.0 (minor, 기능 추가) — 제 판단

## 왜

- 패널을 띄워 둔 채 다른 앱에서 작업(붙여넣기 등)하고 싶은데, 지금은 포커스를 잃으면 패널이 내려간다.
- 큰 모니터에서는 패널(최대 360pt)이 작아 카드 내용을 보기 답답하다.
- macOS에서 단축키 변경이 안 되고, 패널을 열 때 최신 카드가 간헐적으로 선택되지 않는다.

## 공통 원칙

- 새 의존성 없음.
- macOS·Windows 모두 동작해야 한다.
- 새 문자열은 `src/i18n/ko.ts`, `src/i18n/en.ts` 둘 다에 넣는다.
- 기존 "카드 고정"(📌, `Cmd+P`)과 이름·아이콘이 헷갈리지 않게 한다. 새 기능은 UI에서 "패널 고정"으로 부르고 📌가 아닌 아이콘을 쓴다.

## 1. 버그: macOS에서 단축키 변경이 안 됨

파일: `src/settings/ShortcutRecorder.tsx`

추정 원인: macOS WebKit은 `<button>`을 클릭해도 포커스를 주지 않는다. 그래서 버튼에 단 `onKeyDown`이 불리지 않는다(`onBlur`도 마찬가지).

- 구현 전에 실제로 재현해서 원인을 확인한다(`superpowers:systematic-debugging`).
- 추정이 맞다면 녹화 시작 시 버튼에 명시적으로 `focus()`를 주거나, 녹화 중에는 `window` 단위 keydown 리스너로 받는다. 방법은 빌더 판단이다.
- 기존 동작은 유지한다: `Esc`로 취소, 등록 실패 시 에러 표시, 실패하면 이전 단축키로 복귀(백엔드 `set_shortcut`).
- 녹화 중에 현재 전역 단축키(`⌘⇧V`)를 누르면 패널이 열리지 않고 녹화 입력으로 들어가야 한다. 지금도 그렇게 되는지 함께 확인한다.

## 2. 버그: 패널을 열 때 최신 카드가 선택되지 않음

파일: `src/panel/Panel.tsx`

원인: `panel://closed`에서 선택을 최신 카드로 초기화한다. 그 뒤 패널이 숨겨진 동안 새 복사가 들어오면 `clips://changed` → `reload(true)` → `followSelection`이 이전 선택 카드를 따라간다. 그래서 새 카드가 맨 앞에 들어와도 선택은 한 칸 옆의 예전 카드에 남는다.

요구 동작(사용자 결정):

1. 패널을 열 때 선택은 **항상** 최신 카드다. `defaultSelection`과 같은 규칙으로, 히스토리가 비어 있으면 첫 고정 카드.
2. 패널이 떠 있는 상태(고정 여부 무관)에서 **새 클립이 들어오면** 선택이 최신 카드로 옮겨간다.
3. 그 밖의 목록 변경(카드 고정/해제, 삭제, 보관 기간 정리 등)은 지금처럼 선택한 카드를 따라간다. 커밋 f7392b6의 동작을 유지한다.

2와 3을 구분하려면 `clips://changed`가 "새 클립 도착"인지를 알려야 한다. 페이로드를 추가할지, 이벤트를 따로 둘지는 빌더 판단이다. 새 카드가 들어오는 FLIP 애니메이션은 유지한다.

선택 규칙은 `src/panel/selection.ts`에 두고 `selection.test.ts`에 테스트를 추가한다.

## 3. 패널 고정

### 동작 (사용자 결정)

- 고정하면 **고정을 풀 때까지** 패널이 내려가지 않는다.
  - 다른 앱을 클릭해도(포커스 잃음) 그대로다.
  - `Enter`, 더블클릭, `Shift+Enter`로 복사해도 그대로다. 효과음은 지금처럼 나온다.
    - **포커스는 직전 앱으로 돌려준다(사용자 결정).** 패널은 떠 있고 포커스만 넘어가므로 바로 `⌘V`로 붙여넣을 수 있다.
    - `prev_app_pid`는 패널을 열 때만 기록되고 `hide_panel`에서 `take()`된다. 그러므로 고정 중에는 숨기기만 막고 포커스 복원은 유지해야 한다. 복사할 때마다 돌려줄 앱이 남아 있어야 하므로, 고정 중에는 `take()` 대신 값을 남겨 두거나 패널이 포커스를 얻을 때마다 다시 기록한다(방식은 빌더 판단).
    - 고정 중 "복사됨" 토스트는 카드를 가리지 않도록 화면 하단이 아니라 **패널 바로 위**에 띄운다(제 판단). `toast_rect`와 그 테스트를 바꿔야 한다.
  - `Esc`를 눌러도 패널이 닫히지 않는다. 검색 제안 목록 닫기처럼 `Esc`의 다른 역할은 그대로 둔다.
  - 전역 단축키나 트레이 "열기"를 눌러도 닫히지 않는다. **대신 패널이 포커스를 가져온다(사용자 결정).** 이때 동작은 다음과 같다.
    - 다른 앱에서 키보드만으로 패널로 돌아오는 경로다.
    - 패널을 새로 연 것처럼 취급한다: `prev_app_pid`를 다시 기록하고, 검색어·필터·앱 태그를 비우고, 최신 카드를 선택한다(2장 규칙 1).
    - 패널이 이미 포커스를 가진 상태라면 아무것도 하지 않는다(제 판단).
    - 패널은 다른 모니터에 있어도 그 자리에 그대로 둔다(제 판단).
  - 드래그로 카드를 패널 밖에 놓았을 때 패널이 내려가는 동작(`windows.rs` 드롭 처리 중 `hide_panel`)도 고정 중에는 일어나지 않는다. 카드가 패널 밖으로 나갈 때 "아래로 비켜나는" 연출은 빌더 판단이지만, 끝나면 원위치로 돌아와야 한다.
- 고정을 풀면 지금과 똑같이 동작한다. 단, 풀 때 패널을 바로 닫지는 않는다.
- 고정 상태는 메모리에만 둔다. 앱을 재시작하면 풀린 상태다(제 판단).
- 고정 중에 설정 창(`Cmd+,` / ⚙︎)을 열어도 패널은 그대로다.

### 판단 위치

"내려가지 않음"은 백엔드 한 곳에서 판단한다. `hide_panel`을 부르는 경로가 포커스 잃음(`lib.rs`), 복사 후 닫기, 토글, `Esc`(프론트 `hide_panel` 커맨드), 드롭 등 여러 곳이기 때문이다. `AppState`에 `panel_pinned: AtomicBool`을 두고 `windows::hide_panel` 맨 앞에서 막는 것을 권장한다. 다만 앱 종료나 업데이트 재시작처럼 반드시 닫아야 하는 경로가 있는지는 빌더가 확인한다.

프론트는 토글 버튼에서 `set_panel_pinned(bool)` 커맨드를 부르고, 상태를 화면에 반영한다.

### UI (목업 C안)

- 툴바 오른쪽, ⚙︎ 왼쪽에 아이콘 버튼(`.icon-btn` 계열, 26px, radius 8px).
  - 꺼짐: muted 색.
  - 켜짐: `--accent-subtle` 배경 + `--accent` 색.
  - `aria-pressed`와 `aria-label`("패널 고정" / "Pin panel")을 단다. 툴팁도 같은 문구로 둔다.
- 고정 중에는 패널 전체에 `--accent` 1.5px 링(`box-shadow: 0 0 0 1.5px var(--accent)`)을 두르고, 패널 위 오른쪽 가장자리에 "고정됨" 배지를 표시한다.
  - 배지: `--accent` 배경, 흰 글자, 10px, radius 6px.
- 아이콘은 📌가 아닌 것으로 한다. 목업에서는 임시로 `⊼`를 썼고, 실제 글리프나 SVG는 빌더 판단이다(기존처럼 텍스트 글리프 또는 인라인 SVG).
- 키보드 단축키는 이번 범위에 넣지 않는다.

## 4. 패널 크기 조절

### 설정 (목업 S2안)

파일: `src/settings/Settings.tsx`, `src-tauri/src/settings.rs`

- 새 행 **"패널 크기 조절"**: 기존 `.switch` 토글이고 기본값은 꺼짐(제 판단). 힌트는 "패널 위 가장자리를 끌어 높이를 바꿉니다 (최대 화면의 50%)".
- 새 행 **"패널 크기 초기화"**: 버튼 하나.
  - 누르면 **모달 확인창**이 뜬다. 설정 창 안의 오버레이 + 가운데 카드이고, 제목 "패널 크기 초기화", 본문 "패널 높이를 기본값으로 되돌립니다. 계속할까요?", 버튼 [취소] [초기화(위험색)]로 구성한다.
  - 이 앱에 모달은 처음이다. `role="dialog"`, `aria-modal`을 달고, `Esc`와 배경 클릭은 취소로 처리하며, 열릴 때 취소 버튼에 포커스를 준다.
  - 확인하면 저장된 크기를 지운다. 패널이 떠 있다면 즉시 기본 높이로 다시 배치한다.
  - 이미 기본 크기면 버튼을 비활성화한다(제 판단).
  - 토글이 꺼져 있어도 초기화 버튼은 쓸 수 있다. 토글을 꺼도 늘린 크기는 유지되기 때문이다.
- 설정 키(제안): `panelResize`(`on`/`off`, 기본 `off`), `panelHeightRatio`(빈 값이면 기본 크기).

### 패널에서의 동작

- 토글이 켜져 있으면 패널 위 가운데에 작은 손잡이 바(목업 C안, 회색 28px × 4px)를 보여 준다. 패널 위 가장자리 전체에 ↕ 리사이즈 커서 영역을 둔다.
- 위로 끌면 높이가 늘고 아래로 끌면 줄어든다. **패널 아래쪽은 고정**되고 위로만 커진다. 너비는 지금처럼 화면 폭에 맞춘다.
- 범위
  - 최소: 그 모니터의 기본 높이(`panel_height(work_h)`, 300~360pt).
  - 최대: 커서가 있는 모니터 작업 영역 높이의 **50%**.
- 카드는 높이에 비례해서 커진다. 지금도 카드 크기·글꼴·아이콘이 `100vh` 기준이라 창 높이만 바뀌면 따라온다. 끄는 동안 이 동작이 자연스러운지 확인한다.
- 놓을 때 높이를 **작업 영역 높이 대비 비율**로 저장한다(제 판단). 모니터가 바뀌면 그 비율에 범위를 다시 적용한다.
- 토글을 끄면(사용자 결정) **늘려 둔 크기는 유지**되고 끌 수만 없게 된다. 기본 크기로 되돌리는 방법은 초기화 버튼뿐이다.
- 고정 중에도 크기 조절이 가능하다.
- 구현 방식(창 리사이즈 API vs 포인터 드래그로 높이를 계산해 `place()` 호출)은 빌더 판단이다.
  - 패널 창은 `resizable: false`이다.
  - 위치·크기 계산은 `windows.rs`의 `panel_rect` / `place` / `USES_POINTS` 체계를 그대로 쓴다. macOS(points)와 Windows(physical px)에서 모두 맞아야 한다.
  - 높이 클램프 같은 순수 계산은 `windows.rs`의 기존 테스트 스타일로 단위 테스트를 남긴다.

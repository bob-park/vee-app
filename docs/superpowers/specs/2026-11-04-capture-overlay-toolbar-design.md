# 캡처 오버레이 툴바 · 둥근 창 하이라이트 설계

- 날짜: 2026-11-04
- 브랜치: `feature/capture-overlay-polish`
- 목업: `.superpowers/brainstorm/69955-1793772844/content/toolbar-a.html`, `record-pill.html` (커밋 안 됨)

## 의도

스크린 캡처/녹화 오버레이(`src/app/capture/CaptureApp.tsx`)를 더 현대적으로 다듬는다.

1. Space로 창을 고를 때 파란 하이라이트가 각진 사각형이라 실제 창(둥근 모서리)과 어긋나 보인다. 창 모양을 따라가게 한다.
2. 화면 하단 가운데의 글자 안내("드래그해서 선택 · space 창 · esc 취소")를 **클릭할 수 있는 툴바**로 바꾼다. 여기서 캡처↔녹화, 영역↔창을 마우스로 바꿀 수 있다.
3. 지금은 모든 모니터에 안내가 뜬다. **마우스가 있는 모니터에만** 툴바를 보인다.

## 목표

- 창 하이라이트(`tint`)와 녹화 예정 점선(`planned`, 창을 고른 경우)에 둥근 모서리: macOS 12, Windows 8(논리 px).
- 하단 툴바(목업 A안): 한 줄 글래스 알약 `[캡처|녹화] · [영역|창] · ✕`.
  - 캡처 선택 시 보라(`text-primary`), 녹화 선택 시 빨강(녹화 색). 영역/창은 아이콘 + 라벨.
  - ✕ = 취소(Esc와 같음).
  - 툴바에는 단축키 키캡을 표시하지 않는다.
- 단축키
  - `Space`: 영역↔창 (지금과 같음)
  - `Tab`: 캡처↔녹화 (새로 추가). 녹화 대기 알약이 떠 있는 동안은 Tab이 원래 포커스 이동이다.
  - `Esc`: 취소 (지금과 같음)
  - `Enter`: 녹화 대기 중 녹화 시작 (지금과 같음)
- 녹화 대기 알약: 녹화 모드에서 영역/창을 고르면 **툴바는 그대로 두고 그 위에** 알약을 띄운다.
  - 내용: `[MP4|MOV|WEBM|GIF] ● 녹화 시작`. 순서는 `RECORD_FORMATS`, FFmpeg가 필요한 포맷은 지금처럼 비활성.
  - 스타일은 툴바와 같은 글래스 알약이다. 녹화 시작 버튼은 **빨강 단색**(목업 2번)이다.
  - 알약의 ✕는 없앤다(툴바의 ✕로 일원화).
- 툴바와 알약은 커서가 있는 모니터의 오버레이에만 렌더한다.

## 비목표

- 창의 실제 모양(픽셀 알파) 분석. 고정 반지름으로 충분하다.
- 툴바 위치 이동이나 드래그, 툴바에 단축키 안내 다시 넣기.
- 오버레이를 여는 단축키 동작 변경. 캡처 단축키는 캡처 모드로, 녹화 단축키는 녹화 모드로 연다(지금 그대로).
- 캡처 결과물(이미지)의 모서리 처리 변경.

## 안티 목표

- 녹화기 상태 머신(`recorder::Phase`)과 오버레이 모드가 어긋나는 것. 예: 녹화로 바꿨는데 녹화기가 Idle이라 시작이 거부되거나, 캡처로 바꿨는데 녹화기가 Selecting에 남아 다음 녹화 단축키가 무시되는 경우.
- 다른 모니터 오버레이가 다른 모드를 보여주는 것.
- 툴바 클릭이 드래그 시작으로 새는 것(`stopPropagation` 필요).

## 제약

- 색은 `globals.css` 토큰만 쓴다. 빨강 버튼에 쓸 토큰이 없으면 녹화 테두리 색(`stroke-rec`의 토큰)을 재사용하거나 새 토큰을 라이트/다크 양쪽에 둔다.
- 사용자 문구는 `src/shared/i18n/{en,ko}.ts`에 둔다. `capture.regionHint`/`windowHint`는 툴바가 대신하므로 지우고, 라벨(`캡처`, `녹화`, `영역`, `창`, 툴바 aria-label 등)을 새로 추가한다.
- 기존 컴포넌트 `Segmented`(`src/shared/components/Segmented.tsx`)를 쓸 수 있으면 재사용한다. 아이콘 라벨이 안 되면 최소한으로 확장한다.
- 새 Tauri 명령은 [tauri-commands](../../agents/conventions/tauri-commands.md) 규칙을 따른다(얇은 command, `call()` 래퍼, capability, 이벤트 이름 `capture://...`).
- 라이트/다크와 한국어/영어에서 모두 확인한다. 툴바 버튼에는 접근성 역할(`radiogroup`/`radio`)과 `:focus-visible`을 둔다.

## 접근 방식 (검토한 것과 선택)

### 둥근 모서리
- **선택: OS별 고정 반지름.** SVG `rect`의 `rx`/`ry`와 mask 안 `rect`에 같은 반지름을 준다. 프론트만 바뀐다. 각진 창(일부 Windows 앱, 전체 화면)도 둥글게 보이는 한계는 받아들인다.
- 기각: 창 이미지 알파로 실제 모양 추출. 정확하지만 Space마다 창별 캡처가 필요해서 무겁고, OS별 코드도 든다.

### 캡처↔녹화 전환
- **선택: Rust에 모드 변경 명령 추가.** 세션의 모든 오버레이 `payload.mode`를 바꾸고, 녹화기 상태를 맞추고, 모든 오버레이에 이벤트로 알린다. 기존의 `record_target`이 `mode == Record`를 검사하는 안전장치를 그대로 둘 수 있다.
- 기각: 프론트에서만 모드를 관리하고 요청 시 모드를 넘기는 방식. Rust 검사를 없애야 하고, 녹화 단축키와의 연동(`Phase::Selecting`)이 어긋나기 쉽다.

## 결정된 동작

### 모드 변경 (Rust)
- 새 명령, 예: `set_capture_mode(mode) -> AppResult<Mode>` (이름은 빌더 재량). 실제로 적용된 모드를 돌려준다.
- **캡처 → 녹화:** 녹화기가 `Idle`이고 녹화 가능 조건을 통과할 때만 허용한다. 녹화기를 `Selecting { session }`으로 보낸다. 오버레이를 새로 열지 않으므로 `OpenOverlay` 액션 없이 상태만 바꾸는 새 이벤트나 함수가 필요하다.
  - **녹화할 수 없으면 미리 비활성화한다(사용자 결정).** 토스트는 띄우지 않고 설정 창도 열지 않는다. macOS에서는 오버레이(`NSScreenSaverWindowLevel`)가 토스트를 가리고, Windows에서는 `show_settings`가 오버레이의 키보드를 뺏기 때문이다.
  - 세션 payload에 "녹화 불가 이유"를 싣는다. 예: `recordBlocked: null | 'recording' | 'unsupported' | 'needsFfmpeg'`. 이유는 세 가지다: 녹화기가 `Idle`이 아님, `screen_access::recording_supported()`가 false, Windows에서 FFmpeg 없음.
  - 지금의 `can_record`는 토스트와 설정 창을 띄우는 부작용이 있다. 부작용 없이 이유만 돌려주는 판정 함수로 나누고, `can_record`는 그 함수를 감싸 기존 부작용을 유지한다.
  - 막혀 있으면 툴바의 "녹화" 세그먼트는 비활성이고, 마우스를 올리면 `title`로 이유를 보여준다(i18n은 기존 `record.unsupported`/`ffmpegNeeded` 재사용 가능). Tab은 무시한다.
  - `set_capture_mode`도 같은 판정으로 다시 검사해서 거부한다(경쟁 상태 대비). 이때는 조용히 현재 모드를 돌려준다.
- **녹화 → 캡처:** 녹화기를 `Selecting` → `Idle`로 되돌린다(`overlay_closed`와 같은 `Event::Cancel`).
- 변경 뒤 `capture://mode-changed` 같은 이벤트를 모든 오버레이에 보낸다. 각 오버레이는 `open.mode`를 갱신하고, 대기 중 선택(`pending`)과 `windowPicked`를 지운다. 영역/창 모드는 유지한다.
- `cancel_capture`는 세션의 **현재** 모드를 보고 `overlay_closed`를 부른다(지금은 첫 오버레이의 payload를 본다. 모두 같이 바뀌므로 그대로 동작해야 한다).

### 툴바 표시 모니터
- 오버레이는 `pointer`(마우스가 이 모니터 위면 값이 있음, 처음엔 `session.cursor`)가 있을 때만 툴바와 알약을 그린다. 마우스가 다른 모니터로 가면(`onPointerLeave`) 사라지고 그쪽에 나타난다.
- 녹화 대기 알약은 선택한 모니터에만 있다. 그 모니터를 떠나면 알약도 숨기고, 돌아오면 다시 보인다(`pending`은 유지된다).

### Tab과 녹화 대기 선택 (설계자 판단)
- Tab은 **이 오버레이에 녹화 대기 알약이 보일 때만** 포커스 이동이고, 그 밖에는 모드 전환이다.
- 다른 모니터에 골라 둔 녹화 선택이 있어도 Tab은 모드를 바꾼다. 선택은 지워진다. 툴바에서 "캡처"를 클릭할 때와 같은 동작이라 따로 추적할 상태를 두지 않는다.

### 기타
- 드래그 중(`dragFrom`)에는 지금처럼 툴바와 알약을 숨긴다.
- 커서 모양(`cursor-camera`/`cursor-record`)은 바뀐 모드를 따른다.
- 페이드 애니메이션은 기존 `duration-150`과 reduced-motion 규칙을 따른다.

## 빌더에게 맡기는 것
- 명령, 이벤트, i18n 키 이름(네이밍 규칙 안에서).
- 반지름 상수의 위치(`captureSelection.ts` 등)와 OS 판별 방법(이미 있는 `isMac` 재사용).
- 툴바를 `CaptureApp` 안에 둘지 `src/app/capture/_components/`로 뺄지.
- 테스트: 녹화기 상태 전이(`next`)의 새 경로와 세션 모드 변경은 Rust 단위 테스트로, 순수 함수가 생기면 `node:test`로 확인한다.

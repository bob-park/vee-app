# 자동 다음 붙여넣기 — 설계

## 의도

히스토리의 여러 항목을 패널을 다시 열지 않고 연달아 붙여넣는다. 설정을 켜면 Cmd+V(Windows는 Ctrl+V)를 누를 때마다 클립보드가 패널에 보이는 순서의 다음 카드로 넘어간다.

## 목표 / 비목표 / 안티 목표

- 목표
  - 설정 화면에서 켜고 끌 수 있다. 기본값은 꺼짐.
  - 켜져 있으면 Cmd+V 한 번마다 패널 순서(최신 → 과거)로 한 카드씩 붙는다.
  - macOS와 Windows 모두 동작한다.
- 비목표
  - 전용 "다음 붙여넣기" 단축키, 복사한 순서(과거 → 최신) 모드, 순서 되감기.
  - 패널에 "지금 차례인 카드" 표시.
  - 메뉴의 "붙여넣기", 우클릭 붙여넣기, Cmd+Shift+V 같은 다른 붙여넣기 키 감지.
- 안티 목표
  - Vee 때문에 Cmd+V가 느려지거나 먹통이 되는 것. Vee는 키를 가로채지 않는다.
  - 꺼져 있는데 키 입력을 지켜보는 것.
  - 붙여넣을 때마다 패널 순서가 바뀌는 것.
  - 눌린 키를 저장하거나 로그로 남기는 것.

## 제약

- 지금 Vee는 붙여넣기를 하지 않는다. `copy_clip`(`src-tauri/src/app/window.rs`)이 클립보드에 쓰고, 붙여넣기는 OS가 한다. 이 구조를 유지한다.
- `confirm_copy`는 카드를 `clip::touch`로 맨 위로 올리고 토스트와 소리를 낸다. 자동 넘김은 이 경로를 타면 안 된다.
- 패널 순서는 `ORDER BY last_used_at DESC, id DESC`(`domain/clip/repository.rs`)다.
- Vee가 쓴 클립보드는 `state.suppress_watcher()`로 워처가 무시한다. `write_clipboard`가 이미 그렇게 한다.
- macOS에서 다른 앱의 키 입력을 보려면 **입력 모니터링** 권한이 필요하다. Windows는 권한이 필요 없다.
- 새 crate는 추가하지 않는다. 이미 있는 `objc2-core-graphics`, `objc2-core-foundation`, `windows`를 쓴다. 이 crate들의 feature 플래그를 더 켜야 하면 `Cargo.toml` 변경이므로 사용자 확인을 먼저 받는다.
- 플랫폼 코드는 `#[cfg]` 뒤에 두고, `domain/`에는 `tauri`를 들이지 않는다(`docs/agents/conventions/rust-modules.md`).

## 접근 방식

| 방법 | 내용 | 판단 |
| ---- | ---- | ---- |
| 1. 가로채서 대신 붙여넣기 | Cmd+V를 전역 단축키로 등록하고, 클립보드를 채운 뒤 가짜 Cmd+V를 보낸다 | 제외. 손쉬운 사용 권한이 필요하고, 가짜 키가 단축키에 다시 걸리지 않게 등록을 풀었다 걸어야 하며, Vee가 멈추면 Cmd+V가 먹통이 된다 |
| 2. 지켜보고 뒤에서 교체 | 키 입력을 읽기 전용으로 감지하고, 붙여넣기 직후 클립보드를 다음 카드로 바꾼다 | **선택(사용자)**. 붙여넣기는 OS가 그대로 하므로 Vee가 죽어도 Cmd+V는 동작한다. 대가는 macOS 입력 모니터링 권한과, 아주 빠른 연타에서 같은 카드가 두 번 붙을 수 있다는 점 |
| 3. 전용 단축키 | Cmd+V는 두고 새 단축키로 "다음 붙여넣기" | 제외. 요구사항이 "cmd + v 시"다 |

## 설계

### 동작

- **차례(cursor)**: "지금 클립보드에 올라 있는 카드"의 id를 `AppState`에 둔다.
  - 워처가 새 복사를 기록하면 그 카드가 차례가 된다(맨 위).
  - Vee가 카드를 실제로 클립보드에 썼을 때(`write_clipboard`가 성공한 경로: 패널 복사, 편집기 복사 등) 그 카드가 차례가 된다. 이때는 기존대로 맨 위로 올라간다. 드래그로 꺼내기(`finish_drag`)는 클립보드에 쓰지 않으므로 차례를 바꾸지 않는다.
  - **차례 모름**: 앱을 막 켰을 때, 그리고 클립보드가 Vee가 기록하지 않은 내용으로 바뀌었을 때(비밀번호 관리자의 숨김 복사, 제외한 앱, 빈 텍스트, 너무 큰 이미지)는 차례가 없다. 차례가 없으면 **넘기지 않는다**. 다음에 기록되는 복사나 Vee에서의 복사부터 다시 시작한다. 사용자가 방금 복사한 내용을 Vee가 옛 카드로 덮어쓰는 일을 막기 위해서다.
  - 구현은 워처가 실제 클립보드 변경을 볼 때마다 차례를 지우고, 기록에 성공하면 그 카드로 채우는 식이면 된다.
- **고정 카드**: 순서는 패널의 히스토리 목록(고정 안 된 카드)만 따른다. 고정 사이드바의 카드는 순서에 들어가지 않는다. 고정 카드를 복사해 차례가 된 경우 다음 카드는 히스토리 맨 위다. 조회는 "차례 카드의 `(last_used_at, id)`보다 뒤에 오는 첫 번째 고정 안 된 카드"로 하면 두 경우가 같은 쿼리로 풀린다.
- **넘김**: Cmd+V가 감지되면 약 150ms 뒤, 차례 카드 바로 다음 카드(검색·필터 없는 전체 목록 기준)를 클립보드에 쓰고 차례를 그 카드로 옮긴다.
  - `clip::touch` 없음, 토스트 없음, 소리 없음, 패널 숨김 없음, `clips://changed` 없음.
  - 저장된 원본 포맷을 그대로 쓴다(`plain` 아님).
  - 다음 카드가 없으면(마지막) 아무것도 하지 않는다.
  - 차례 카드가 지워졌으면 차례 모름으로 돌아간다(넘기지 않음).
  - 넘김으로 쓴 클립보드는 워처가 무시해야 하지만, 지금의 1.2초 무시 구간(`suppress_watcher`)을 그대로 쓰면 붙여넣은 직후의 실제 복사가 기록되지 않고 다음 붙여넣기 때 덮어써진다. 넘김 경로는 무시 구간을 워처 폴링(200ms)을 덮는 최소한(0.5초 이하)으로 줄인다.
  - 쓸 수 없는 카드(파일이 사라진 파일 카드 등)는 건너뛰고 그다음 카드를 쓴다.
- **연타**: 넘김이 대기 중일 때 들어온 Cmd+V는 버린다. 150ms 안에 두 번 누르면 같은 카드가 두 번 붙고 한 번만 넘어간다. 카드를 건너뛰는 일은 없다.
- **감지 대상**: 정확히 Cmd+V(Windows는 Ctrl+V) key down만. 다른 수정 키가 함께 눌렸거나 키 반복(꾹 누름)이면 무시한다.
- **Vee 자체 창**: 맨 앞 앱이 Vee면 무시한다(`front_app::frontmost`).

### 구성

- **설정 키**: `autoNextPaste`, 값 `on`/`off`, 기본 `off`. `SettingsDto`, `settings::get` 기본값, 프런트 DTO에 추가한다. 마이그레이션은 필요 없다(settings는 key-value).
- **다음 카드 조회**: `domain/clip/repository.rs`에 "주어진 카드 다음 카드"를 돌려주는 함수를 둔다. 패널 목록과 같은 정렬을 쓴다. 단위 테스트 대상.
- **키 감시**: `src-tauri/src/app/`에 새 모듈 하나.
  - macOS: listen-only 이벤트 탭(`CGEventTap`)을 전용 스레드의 run loop에서 돌린다.
  - Windows: `WH_KEYBOARD_LL` 훅을 전용 스레드의 메시지 루프에서 돌린다.
  - 설정이 `on`일 때만 감시를 건다. 시작할 때 설정을 읽고, 설정이 바뀌면 걸거나 푼다.
  - 감시 콜백은 채널로 신호만 보낸다. 넘김(대기, DB 조회, 클립보드 쓰기)은 별도 워커 스레드가 한다. 콜백에서 오래 걸리면 OS가 탭/훅을 끊는다.
- **권한(macOS)**: 권한 탭(`PermissionsSection`)에 "입력 모니터링" 행을 추가한다. 화면 기록 행과 같은 모양(허용 버튼 → 시스템 설정 열기, 허용됨 배지)이고, 기능이 꺼져 있으면 흐리게 한다. 스위치를 켤 때 권한이 없으면 OS 권한 요청을 띄운다. 권한이 없으면 기능은 조용히 동작하지 않고, 스위치 행의 힌트가 권한이 필요하다고 알려 준다.
- **설정 UI**: 일반 탭에 기존 `Row` + `Switch`로 한 줄. 문구는 `src/shared/i18n/{en,ko}.ts`에 둔다.
  - ko: "자동 다음 붙여넣기" / 힌트 "붙여넣을 때마다 클립보드가 패널의 다음 카드로 넘어갑니다."
  - en: "Auto next paste" / hint "Each paste moves the clipboard to the next card in the panel."
- **문서**: `docs/agents/overview.md`(Rust side, 권한), `architecture.md`, `configuration.md`에 새 감시와 권한을 반영한다.

### 검증

- `next` 조회(고정 카드, 마지막 카드, 지워진 카드 포함), 차례 지우기/채우기, 연타 버리기 로직은 `cargo test` 단위 테스트.
- 네 가지 검사(`cargo test --lib`, `yarn test`, `yarn typecheck`, `yarn lint`) 통과.
- 개발 앱을 띄워 텍스트 편집기에 Cmd+V를 연달아 눌러 순서를 확인한다. 설정 화면은 라이트/다크, 한국어/English로 본다.

## 내가 정한 것 (사용자가 정하지 않음)

- 설정 위치는 일반 탭, 기본값 꺼짐.
- 지연 150ms. 구현 중 실제 앱(브라우저, 터미널, 에디터)에서 모자라면 조정한다.
- 연타는 버린다(같은 카드 두 번, 건너뛰기 없음).
- 쓸 수 없는 카드는 건너뛴다.
- Vee가 기록하지 않은 내용이 클립보드에 있으면 넘기지 않는다(앱을 막 켠 직후 포함).
- 순서는 고정 안 된 히스토리만. 고정 카드 다음은 히스토리 맨 위.
- 넘김 뒤 워처 무시 구간은 0.5초 이하. 그 안에 한 복사는 기록되지 않을 수 있다.
- 목업 3종은 생략한다. 새 화면이 아니라 기존 `Row` + `Switch` 한 줄과 기존 모양의 권한 행 한 줄이라 비교할 시안이 없다.

## 빌더에게 맡기는 것

- 모듈·함수·이벤트 이름, 차례를 `AppState`에 두는 구체적인 형태.
- macOS 입력 모니터링 권한 확인/요청 API와, 허용 직후 탭이 바로 걸리는지 재실행이 필요한지 확인. 재실행이 필요하면 화면 기록 행처럼 힌트로 안내한다.
- 필요한 crate feature 플래그 목록(사용자 확인 후 추가).
- Windows 훅 스레드의 종료 방식.

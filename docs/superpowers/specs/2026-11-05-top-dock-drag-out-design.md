# 위쪽 도킹에서 카드를 아래로 끌어내기 (작은 수정)

## 의도

패널을 화면 위쪽에 도킹하면, 카드를 아래로 끌어 Finder 등에 놓으려 할 때 OS 드래그가 시작되지 않는다.
지금은 카드를 한 번 위로 올렸다가 다시 내려야 드롭된다. 어느 방향으로 끌어도 창 밖으로 나가는 순간 OS 드래그가 시작되도록 고친다.

## 원인

- `floatCard`(`src/app/panel/_components/motion.ts`)는 창 안에서 복사본 카드가 커서를 따라다니게 하고, `ghostLeaves`가 참이면 OS 드래그로 넘긴다.
- `ghostLeaves`(`src/utils/motion.ts`)는 위·왼쪽·오른쪽만 검사하고 아래쪽은 보지 않는다. 패널이 늘 아래쪽에 도킹되던 시절의 가정이 남은 것이다(`443558f`에서 다른 가장자리 도킹이 추가됨).
- 마우스 버튼을 누른 채로는 WebKit이 `mouseleave`를 보내지 않으므로, 아래로 끄는 드래그를 넘겨받을 수단이 없다.

## 목표 / 비목표

- 목표: 위쪽·왼쪽·오른쪽 도킹에서 아래로 끌어도 창 밖으로 나가면 OS 드래그가 시작된다.
- 비목표: 드래그 이미지, 패널이 밀려 나가는 애니메이션, Rust 쪽 드래그 처리는 건드리지 않는다.
- 사용자 결정: 아래쪽 검사를 모든 도킹에 똑같이 적용한다. 따라서 아래쪽 도킹에서도 카드를 들어 올린 위치보다 더 아래로 끌면 OS 드래그가 시작된다(지금은 아무 일도 일어나지 않음).

## 접근 방법

1. **(선택)** `ghostLeaves(box, start, w, h)`: 창 높이 `h`를 받아 `box.bottom > Math.max(h, start.bottom)`을 다른 세 방향과 같은 규칙으로 검사한다. 들어 올릴 때 이미 삐져나온 만큼은 봐준다. 변경이 가장 작고, 위치별 분기가 없다.
2. 도킹 위치(`position`)를 받아 방향마다 다르게 검사: 모든 도킹에 똑같이 적용하기로 했으므로 필요 없는 분기다.
3. `mouseleave`에만 의존: 버튼을 누른 동안 WebKit이 이벤트를 보내지 않으므로 동작하지 않는다.

## 변경 범위

- `src/utils/motion.ts`: `ghostLeaves`에 `h` 인자와 아래쪽 검사를 추가하고, "아래쪽은 세지 않는다"는 주석을 고친다.
- `src/app/panel/_components/motion.ts`: 호출부에 `innerHeight`를 넘긴다.
- `src/utils/motion.test.ts`: "아래로 끄는 것은 절대 드래그가 아니다"를 전제로 한 기존 케이스를 새 규칙(삐져나온 만큼보다 더 내려가면 참)으로 바꾸고, 위쪽 도킹에서 아래로 끄는 케이스를 추가한다.

## 검증

`cargo test --manifest-path src-tauri/Cargo.toml --lib`, `yarn test`, `yarn typecheck`, `yarn lint`를 돌린다. 그다음 `yarn tauri dev`로 위쪽·아래쪽·왼쪽·오른쪽 도킹에서 각각 카드를 Finder로 끌어내 직접 확인한다.

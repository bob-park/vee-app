# 패널 위치 설정 설계

- 날짜: 2026-10-23
- 브랜치: `feature/panel-position` (master에서 분기)

## 왜

지금 패널은 늘 화면 하단에 붙는다. 사용자가 패널을 하단·상단·왼쪽·오른쪽 중 원하는 가장자리에 띄울 수 있게 한다. 같은 작업에서 What's New 창 기본 크기도 키운다.

## 사용자가 정한 것

1. 새 브랜치에서 작업한다.
2. 위치는 **하단 / 상단 / 왼쪽 / 오른쪽** 네 가지다. **기본값은 하단**이다.
3. 설정(패널 탭)에서 고른다. UI는 **B안(미니 화면 타일)**으로 한다.
   - 첫 줄에는 "패널 위치" 이름과 설명만 둔다.
   - 둘째 줄에는 타일 4개를 한 줄로 둔다. 섹션 폭을 4칸으로 나누고 각 칸 가운데에 타일을 놓는다. 타일은 테마 타일보다 약간 큰 **폭 84px**, 화면 비율 16:10이다.
   - 참고 목업: `.superpowers/brainstorm/45400-1792752143/content/position-setting-v4.html` (git 밖)
4. **왼쪽/오른쪽**에서는 카드가 위에서 아래로 **세로로 쌓인다**.
5. **왼쪽/오른쪽**에서는 손잡이로 **폭**을 조절한다.
6. **상단**에서도 크기 조절 손잡이가 나온다. 패널 **아래쪽** 가장자리를 아래로 끌면 커진다.
7. **What's New** 창은 **기본 크기만 키운다**. 크기 조절 기능은 넣지 않는다.

## 현재 상태

- 배치: `src-tauri/src/app/window.rs`의 `panel_rect(work, unit, h)`가 작업 영역 하단에 여백 8pt(`PANEL_MARGIN`)를 두고 꽉 찬 폭으로 놓는다. 높이는 `panel_height_for`가 계산한다. 기본은 작업 영역의 30%이고, 15–50% 사이로 제한하며, 저장된 비율은 `panelHeightRatio`에서 읽는다(주 모니터 작업 영역 기준).
- 크기 조절: `ResizeHandle.tsx`는 위쪽 가장자리의 드래그 띠다. `resize_panel(height, save)`는 아래 가장자리를 고정하고 높이를 바꾼다. `reset_panel_height`는 비율을 지운다. `panelResize` 설정(on/off)이 손잡이를 켜고 끈다.
- 레이아웃: `PanelApp.tsx` 본문은 가로 flex다. 왼쪽에 고정 카드, 세로 구분선, 그 오른쪽에 `overflow-x-auto` 목록이 있다. 휠은 `scrollLeft`로 바꾸고, 무한 로딩은 `scrollLeft + clientWidth`로 판단한다. 카드 폭은 `w-[calc((100vh-72px)*0.95)]`, 즉 패널 높이를 따른다.
- 움직임: 열기/닫기/파일 드래그 아웃 때 패널이 `translate-y-[calc(100%+16px)]`로 아래로 빠진다. `motion.ts`의 FLIP은 카드의 `left`만 잰다(`cardLefts`).
- 토스트: 패널이 고정되어 있으면 `show_toast`가 패널 높이 + 여백만큼 토스트를 위로 올린다(하단 가정).
- 설정 저장: key-value 테이블(`settings::get/set/validate`)이다. 새 키에 마이그레이션은 필요 없다.
- What's New: `tauri.conf.json`에서 400×480, `resizable: false`.

## 무엇을 만드나

### 1. 설정

- 새 키 `panelPosition`: `bottom | top | left | right`, 기본 `bottom`. `settings::get` 기본값과 `validate`에 넣고, `SettingsDto`와 TS DTO에도 추가한다.
- 새 키 `panelWidthRatio`: 백엔드만 쓰는 값(`set_raw`)으로, `panelHeightRatio`와 같은 방식이다. 높이 비율은 상단/하단이, 폭 비율은 왼쪽/오른쪽이 함께 쓴다. 그래서 위치를 바꿔도 서로 덮어쓰지 않는다. *(내 판단)*
- 패널 탭 맨 위에 "패널 위치" 줄을 추가한다(`Row`의 `col` 모드). 타일 컴포넌트는 `ThemePicker`와 같은 접근성 규칙을 따른다. `radiogroup`/`radio`, 화살표 키 이동(`arrowStep`), 선택된 타일은 살짝 떠오르고 primary 테두리를 갖는다. 미리보기 화면 색은 `ThemePicker`처럼 `globals.css`의 토큰을 쓴다(새 토큰이 필요하면 라이트/다크 두 값을 모두 둔다).
- "패널 크기 조절" 안내 문구는 위치에 따라 바뀐다.
  - 하단: 위 가장자리를 끌어 높이를 바꿉니다
  - 상단: 아래 가장자리를 끌어 높이를 바꿉니다
  - 왼쪽: 오른쪽 가장자리를 끌어 폭을 바꿉니다
  - 오른쪽: 왼쪽 가장자리를 끌어 폭을 바꿉니다
  - 네 경우 모두 "(최대 화면의 50%)"를 붙인다.
- "패널 크기 초기화"는 **현재 위치의 축**(높이 또는 폭) 비율만 지운다. 버튼은 그 축의 비율이 비어 있을 때 비활성이다. 확인 문구도 축에 맞춘다. *(내 판단)*
- 모든 문구는 `src/shared/i18n/{en,ko}.ts`에 둔다.

### 2. 창 배치 (Rust, `app/window.rs`)

- 패널 직사각형을 위치별로 계산한다. 여백은 모든 방향에 8pt다.
  - 하단: 지금과 같다.
  - 상단: 작업 영역 위쪽에 붙는다. 폭과 높이 계산은 하단과 같다.
  - 왼쪽/오른쪽: 작업 영역 높이 − 2×여백만큼 길게, 해당 가장자리에 붙는다.
- 폭 계산은 높이 계산과 같은 구조다. 주 모니터 작업 영역 **폭** 기준 비율이고, 15–50%로 제한한다.
  - **기본 폭은 작업 영역 폭의 25%**로 한다. *(내 판단)*
  - 툴바가 깨지지 않도록 **최소 폭 340pt**를 둔다(작은 모니터에서 15%가 너무 좁아지는 것을 막는다). 정확한 최소값은 툴바가 실제로 들어가는지 보고 정한다. *(빌더 몫)*
- `resize_panel`은 현재 위치의 축을 바꾼다. 화면 가장자리에 붙은 쪽은 고정하고 안쪽 가장자리만 움직인다. 저장할 때는 해당 축 비율 키에 쓴다. 명령 이름과 인자는 축 중립적으로 바꿔도 되고, 지금 이름에 축을 더해도 된다. *(빌더 몫, `tauri-commands` 규칙 따름)*
- 위치 설정이 바뀌었을 때 패널이 보이고 있으면 그 자리에서 새 위치로 다시 놓는다. 숨겨져 있으면 다음 열 때 적용한다.
- 토스트: 고정된 패널과 겹치지 않게 한다. *(내 판단)*
  - 하단: 지금처럼 패널 위로 올린다.
  - 상단: 올리지 않는다.
  - 왼쪽/오른쪽: 높이는 지금처럼 아래에서 띄운다. 가로 위치만 작업 영역 중 패널이 차지하지 않은 부분의 가운데로 옮긴다.
- 순수 계산 함수(직사각형·크기 제한·토스트 위치)는 위치별 단위 테스트를 둔다. 지금의 `window.rs` 테스트와 같은 형식이다.

### 3. 패널 화면 (프런트)

- 위치는 `useSettings()`의 `panelPosition`으로 읽는다. 세로 모드는 `left | right`일 때다.
- **가로 모드(하단/상단)**: 지금 레이아웃 그대로다. 상단에서는 손잡이가 아래 가장자리로 간다.
- **세로 모드(왼쪽/오른쪽)**:
  - 툴바가 맨 위에 있고, 그 아래 고정 카드, **가로 구분선**, 기록 목록이 위에서 아래로 놓인다.
  - 목록은 `overflow-y-auto`로 세로 스크롤한다. 휠의 가로→세로 변환은 끈다. 무한 로딩은 `scrollTop + clientHeight` 기준이다.
  - 카드 폭은 패널 안쪽 폭을 꽉 채운다. **카드 높이는 낮춰서 여러 장이 한눈에 보이게 한다**(사용자 결정). 가로로 긴 카드로, 고정 카드 3장과 기록 카드 여러 장이 함께 보여야 한다.
    - ~~높이 160pt 고정~~ → 실제로 띄워 본 뒤 **정사각형(높이 = 폭)**으로 바꿨다(사용자 결정, 2026-10-23). 텍스트는 최대 12줄.
    - 카드 안 요소(머리줄, 내용 타일, 아래 줄, 이미지 썸네일, 텍스트 줄 수)는 낮은 높이에 맞게 줄인다. 텍스트 줄 수와 글자 크기는 지금 `100vh` 기준이라, 세로 모드에서는 카드 높이 기준으로 바꾼다.
    - 고정 카드 영역은 따로 스크롤하지 않는다. 기록 목록만 스크롤한다.
  - 키보드 카드 이동은 위/아래 방향키가 맡는다(가로 모드의 좌/우 이동과 대응). 검색 제안 목록이 열려 있으면 위/아래는 지금처럼 제안 목록을 움직인다. 좌/우는 지금처럼 카드 이동으로 남긴다. 그래서 `panelKeyAction`(`src/utils/keys.ts`)이 레이아웃을 입력으로 받는다. `scrollIntoView`는 그대로 쓴다. *(내 판단)*
  - 툴바는 좁은 폭에 맞춰 압축한다. 검색창이 남는 폭을 차지하고 필터는 줄바꿈하거나 줄인다. 모양은 `docs/design/aurora-glass.md`를 따른다. *(빌더 몫)*
  - 고정 카드 개수 초과 안내(`pinNotice`) 등 가로 배치를 가정한 위치는 세로에 맞게 조정한다.
- **열기/닫기/드래그 아웃 슬라이드**는 붙은 가장자리 방향으로 움직인다. 하단은 아래, 상단은 위, 왼쪽은 왼쪽, 오른쪽은 오른쪽이다. 곡선과 시간은 그대로다(`EASE_MOVE` 300ms / `ease-in` 200ms). reduced-motion 처리도 유지한다.
- **FLIP**(`motion.ts`)은 세로 모드에서 `top`을 재서 세로로 미끄러지게 한다. 새 카드 등장(위에서 16px 내려앉음)은 그대로 둔다.
- **ResizeHandle**은 위치에 따라 놓이는 가장자리, 커서(`ns-resize`/`ew-resize`), 드래그 부호, 측정값(`innerHeight`/`innerWidth`, `screenY`/`screenX`)을 바꾼다. 가운데 손잡이 막대도 세로 모드에서는 세로로 선다.
- DOM 훅 클래스(`card` + `data-id`, `update`, `ghost`)는 바꾸지 않는다.

### 4. What's New

- `tauri.conf.json`에서 400×480을 **520×640**으로 바꾼다. `resizable: false`는 그대로다. *(크기 값은 내 판단)*
- 창 안 내용이 늘어난 크기에서 어색하지 않은지 확인한다(빈 공간, 스크롤).

## 목표가 아닌 것

- 패널을 화면 아무 곳에나 끌어 놓는 자유 배치
- 모니터마다 다른 위치 저장
- What's New 창 크기 조절이나 크기 기억
- 패널 위치를 바꾸는 단축키나 트레이 메뉴

## 이러면 실패

- 위치를 바꾼 뒤 패널이 화면 밖으로 나가거나 잘린다(특히 Windows 배율, 여러 모니터).
- 세로 모드에서 키보드 선택·복사·고정·드래그 아웃·변환이 하나라도 가로 모드와 다르게 동작한다.
- 하단 모드의 모양과 동작이 지금과 1픽셀이라도 달라진다.
- 위치를 오가다 저장된 높이나 폭이 사라진다.

## 확인

- `cargo test --manifest-path src-tauri/Cargo.toml --lib`, `yarn test`, `yarn typecheck`, `yarn lint`를 모두 통과한다.
- `yarn tauri dev`로 네 위치 × 라이트/다크 × 한국어/English를 확인한다. 밝은 배경과 어두운 배경 위의 투명 패널 가장자리, 고정 상태의 토스트 위치, 크기 조절, 크기 초기화, 열기/닫기 슬라이드, 파일 드래그 아웃까지 본다.
- macOS를 우선 확인하되, Windows 쪽 코드도 컴파일되고 같은 규칙으로 동작해야 한다.

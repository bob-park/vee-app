# 드래그 파일 변환 설계

- 날짜: 2026-10-20
- 브랜치: `feature/file-convert` (master에서 분기)
- 참고: [Filee](https://github.com/KnifeLemon/Filee) — 키를 누른 채 파일을 끌면 커서 자리에 포맷 도넛이 열리고, 조각에 놓으면 변환된다.
- 목업: `.superpowers/brainstorm/*/content/convert-mockup.html` (A안 도넛 채택)

## 왜

Vee 패널의 이미지·파일 카드를 끌어 바탕화면이나 Finder 창에 놓을 때, 다른 포맷이 필요하면 지금은 놓은 뒤 다른 앱으로 변환해야 한다. Filee처럼 끄는 동작 하나로 "원하는 포맷으로 그 자리에" 떨어뜨리게 한다.

## 사용자가 정한 것

1. 새 브랜치에서 작업한다.
2. 대상은 **이미지 카드와 파일 카드**만. 텍스트·링크 카드는 제외.
3. 동작:
   1. 카드를 끄는 중에 **변환 키**(기본 macOS `Option`, Windows `Ctrl`)를 누르면, **누른 순간의 커서 자리**에 오버레이가 뜬다. 오버레이는 그 자리에 고정되어 움직이지 않는다.
   2. 키를 누른 채 오버레이의 포맷 조각에 놓으면, **오버레이가 뜬 지점의 폴더**에 변환된 파일이 생긴다. 바탕화면이면 바탕화면에.
4. 변환 키는 **설정에서 바꿀 수 있다**.
5. **폴더가 아닌 곳**(다른 앱 창 위 등)에서 키를 누르면 오버레이를 띄우지 않고 **토스트**로 안내한다.
6. 같은 이름의 파일이 있으면 덮어쓰지 않는다(아래 "Claude가 정한 것" 참고).
7. 변환 종류: **이미지, 문서, 영상 모두**.
8. 엔진:
   - 이미지: OS 내장 + 이미 쓰는 `image` 크레이트.
   - 영상: **FFmpeg를 설정 화면에서 내려받는다**. 설정에 다운로드 진행 현황, 현재 설정, 설치 완료 정보(버전·크기·설치일·위치)를 모두 보여준다.
   - 문서: **사용자가 설치한 LibreOffice의 CLI(`soffice --headless`)** 를 쓴다. 없으면 해당 포맷을 비활성으로 보여주고 설치를 안내한다.
9. 오래 걸리는 변환은 **패널의 그 카드에 진행 상태**(막대 + %)를 표시한다.
10. 오버레이 UI는 **A안: 도넛**(Filee 방식). 카드 진행 표시와 설정 화면은 목업 v1 그대로(사용자 이의 없음).
11. 변환 드롭 후 패널은 지금처럼 닫히고, **변환이 끝나면 토스트로 알린다**(완료/실패).
12. **HWP·HWPX는 [rhwp](https://github.com/edwardkim/rhwp)**(MIT, Rust CLI)로 변환한다.

## 목표

- 키를 누르고 놓기까지 끊김 없음: 오버레이가 뜨는 동안 OS 드래그가 끊기지 않는다.
- 이미지 변환: PNG · JPG · WEBP · HEIC(macOS만) · TIFF · BMP · GIF · PDF(이미지 1장 → PDF 1쪽).
- 영상 변환(FFmpeg): MP4(H.264) · WEBM · MOV · GIF · MP3(소리만) · 720p MP4. 진행률은 FFmpeg `-progress` 출력의 `out_time`/전체 길이로 계산.
- 문서 변환(LibreOffice): DOCX · PPTX · XLSX · ODT · DOC · RTF 등 → PDF, DOCX ↔ ODT 등 LibreOffice가 지원하는 대상. (LibreOffice는 최신 HWP를 읽지 못하므로 HWP는 rhwp 담당.) macOS에서 LibreOffice가 없을 때도 `textutil`로 DOCX/RTF/HTML/TXT끼리는 동작.
- HWP 변환(rhwp): HWP/HWPX → PDF, HWP → HWPX, HWPX → HWP.
- 오버레이에는 **끌고 있는 파일에 맞는 포맷만** 나온다. 엔진이 없어 못 하는 포맷은 흐리게 + 이유("LibreOffice 필요", "FFmpeg 필요").
- macOS와 Windows 모두 같은 동작.

## 하지 않는 것

- 텍스트·링크 카드 변환.
- Vee 밖(Finder 등)에서 시작한 드래그를 가로채기. Vee 카드에서 시작한 드래그만 대상.
- 포맷별 세부 옵션(품질 %, DPI, 페이지 범위 등). 영상 기본 화질 3단계만 설정에 둔다.
- 여러 단계를 거치는 변환 경로 탐색(HWP → HWPX → DOCX 같은 Filee의 RoutePlanner). 엔진 하나가 바로 할 수 있는 변환만.
- 도넛 편집(조각 순서·구성 바꾸기), 폴더 감시, 오른쪽 클릭 메뉴.
- LibreOffice를 내려받아 주는 것. 설치 페이지만 연다.
- FFmpeg/LibreOffice를 앱 번들에 넣는 것.

## 실패로 보는 것 (기술적으로 동작해도)

- 키를 눌렀을 때 오버레이가 늦게(체감 200ms 이상) 뜨거나, 뜨면서 드래그가 취소됨.
- 오버레이가 커서를 따라 움직임.
- 원본 파일이 지워지거나 덮어써짐. 기존 파일이 덮어써짐.
- 키를 누르지 않은 평소 드래그가 지금과 달라짐(느려짐, 동작 변경).
- 변환이 패널/메인 스레드를 막아 패널이 버벅임.
- FFmpeg 미설치나 LibreOffice 미설치 때문에 에러 토스트·크래시가 남(대신 비활성 조각과 안내).
- macOS에서 Finder 자동화 권한을 거부했다고 바탕화면 변환까지 안 됨.

## 흐름

1. 사용자가 이미지/파일 카드를 끈다 → 기존 `start_drag`가 OS 드래그를 시작하고 `AppState.dragging = true`.
2. 드래그 중 Rust 쪽이 변환 키 상태를 주기적으로(약 30ms) 확인한다. 키 감시는 드래그 중에만 돈다.
   - macOS: `CGEventSourceFlagsState` (권한 불필요).
   - Windows: `GetAsyncKeyState`.
3. 키가 눌리는 순간, 커서 위치의 **대상 폴더**를 찾는다.
   - 찾음 → 그 좌표를 중심으로 `convert` 오버레이 창을 띄운다.
   - 못 찾음 → 기존 toast 창에 "폴더 위에서만 변환할 수 있어요" 표시. 이번 드래그 동안 같은 토스트를 반복하지 않는다.
4. 오버레이는 끌고 있는 클립(드래그 상태에 저장된 clip id)의 파일 확장자를 보고 포맷 조각을 만든다. 드롭된 경로가 아니라 **clip id**를 기준으로 한다(이미지 클립은 임시 PNG로 스테이징되어 드래그되기 때문).
5. 키를 뗀다 → 오버레이를 닫는다. 이후 드롭은 지금과 같은 일반 복사.
6. 조각 위에서 놓는다 → 변환 작업을 큐에 넣고 오버레이를 닫는다. 오버레이 밖(도넛 중앙 포함)에 놓으면 아무 것도 하지 않는다.
7. 작업은 백그라운드 스레드에서 실행되고, 진행 이벤트로 패널 카드가 상태를 그린다. 결과는 3단계에서 찾은 폴더에 저장된다.

## 대상 폴더 찾기

- **바탕화면**: 커서 아래 최상위 창이 없거나, 데스크톱 창(macOS: Finder의 데스크톱 레벨 창, Windows: `Progman`/`WorkerW`)이면 사용자 바탕화면 경로. 권한이 필요 없다.
  - macOS: `CGWindowListCopyWindowInfo`로 커서 아래 창의 소유 앱·레이어·bounds를 확인(창 제목은 읽지 않으므로 화면 녹화 권한 불필요).
- **열린 Finder 창 (macOS)**: 커서 아래 창의 소유 앱이 Finder이면 AppleScript(`NSAppleScript`)로 Finder 창들의 bounds와 `target`을 물어, 좌표가 들어가는 창의 폴더를 쓴다.
  - 처음 쓸 때 macOS가 **자동화(Automation) 권한**을 묻는다. `Info.plist`에 `NSAppleEventsUsageDescription` 필요.
  - 거부되어 있으면 Finder 창은 "폴더가 아닌 곳"으로 보고 토스트. 바탕화면은 계속 동작.
- **탐색기 창 (Windows)**: `WindowFromPoint` → 최상위 창 → `IShellWindows`에서 같은 HWND의 창을 찾아 현재 폴더 경로를 얻는다.
- 그 외(다른 앱, 특수 폴더처럼 파일 시스템 경로가 없는 경우)는 "폴더가 아님".
- 폴더 탐색은 **키를 누른 순간 한 번만** 한다.

## 오버레이 (A안 도넛)

- 새 창 `convert`: 투명, 테두리 없음, 항상 위, 포커스 안 받음, 작업 표시줄 없음, 모든 데스크톱(toast 창과 같은 설정). 처음엔 숨겨 두고 필요할 때 위치만 옮겨 보여준다(뜨는 속도).
- 창은 도넛 크기(약 240pt)만큼. 중심이 키를 누른 지점.
- 이 창은 파일 드롭을 받아야 한다(Tauri 창의 drag-drop 이벤트로 놓인 위치를 받음). 드롭 좌표로 어느 조각인지 판정.
- 조각: 링 모양, 커서가 올라간 조각은 보라색(`primary`) 채움. 비활성 조각은 흐리게 + 아래 작은 글씨로 이유. 중앙 원에 파일 이름과 "놓을 포맷 선택".
- 조각 수는 파일 종류별 최대 6~8개. 목록과 순서는 코드에 고정(편집 기능 없음).
- 여러 파일 카드: 모든 파일이 같은 종류(이미지/영상/문서)일 때만 그 종류의 포맷을, 섞여 있으면 **모든 파일에 공통으로 가능한 포맷**만. 공통 포맷이 없으면 오버레이 대신 토스트("이 파일들은 함께 변환할 수 없어요").
- 원본과 같은 포맷 조각은 뺀다.
- 색은 `globals.css` 토큰만, 라이트/다크 둘 다. 문구는 `i18n`.

## 변환 작업

- Rust 쪽 새 도메인 `convert`(모델·포맷 표, 엔진 실행, 작업 큐). 엔진 프로세스 실행과 FFmpeg 다운로드는 `tauri` 의존 없이 core에 두고, 명령/이벤트만 얇게.
- 큐: 엔진별 동시 실행 제한(이미지 2, FFmpeg 1, LibreOffice 1, rhwp 1). 여러 파일 카드는 파일마다 작업 하나.
- 이미지 엔진:
  - macOS: `sips`(HEIC·TIFF·JPG·PNG·BMP·GIF 등) 또는 ImageIO. WEBP 쓰기는 `image` 크레이트.
  - Windows: `image` 크레이트(이미 png/jpeg/gif/webp/bmp/tiff 기능 켜짐). HEIC는 Windows에서 제외.
  - 이미지 → PDF: macOS는 `sips`/Quartz, Windows는 간단한 PDF 직접 작성(이미지 1장 1쪽). 방법은 빌더 판단.
- 영상 엔진: 설치된 `ffmpeg` 실행. `-progress pipe:1 -nostats`로 진행률, `ffprobe` 또는 첫 출력의 Duration으로 전체 길이.
- HWP 엔진: `rhwp export-pdf <입력> -o <출력>`, `rhwp export-hwpx <입력> <출력>`, `rhwp convert <hwpx> <hwp>`(Filee `RhwpConverter.cs` 참고). 진행률 없음 → 움직이는 막대. 한글 글꼴 처리는 Filee `RhwpFonts.cs` 참고(빌더 확인).
- 문서 엔진: `soffice --headless --convert-to <ext> --outdir <임시폴더> <파일>` + **Vee 전용 프로필**(`-env:UserInstallation=file:///<app data>/lo-profile`)로 사용자가 열어 둔 LibreOffice와 충돌을 막는다. 진행률 없음 → 카드에 움직이는 막대.
- 출력은 먼저 임시 폴더에 만들고, 끝나면 대상 폴더로 옮기면서 이름을 정한다. 원본은 절대 건드리지 않는다.
- 취소: 카드의 ✕ → 프로세스 종료, 임시 파일 삭제.
- 시간 제한: 문서 5분, 영상 제한 없음(취소 가능), 이미지 1분.

## 패널 카드 진행 표시

- 목업 3번 그대로:
  - 진행 중: 카드 본문 아래쪽 어두운 그라데이션 위에 "→ MP4 변환 중", %, 얇은 막대, 오른쪽 위 ✕. 영상은 꼬리말에 남은 시간.
  - 진행률 모름(LibreOffice): 움직이는 막대, % 없음.
  - 대기: "대기 중 · N번째". 여러 파일은 꼬리말에 "1/3".
  - 완료: 초록 테두리 + "✓ PNG 저장됨", 꼬리말에 폴더 이름, 약 2초 뒤 원래 카드로.
  - 실패: 빨간 테두리 + "변환 실패" + 짧은 이유 + "다시"(같은 포맷·같은 폴더로 재시도).
- 1초 안에 끝나는 작업은 진행 상태 없이 바로 완료 표시만.
- 상태는 Rust → 패널 이벤트로 전달(카드 id 기준). 패널이 닫혀 있어도 작업은 계속, 다시 열면 현재 상태를 받는다.

## 완료 토스트

- 변환 드롭 후 패널은 지금처럼 닫힌다(고정 패널은 열린 채).
- 작업이 끝나면 기존 toast 창으로 알린다:
  - 완료: "PNG로 저장했어요 · 바탕화면"(포맷 · 폴더 이름). 여러 파일이면 "3개 파일을 MP4로 저장했어요".
  - 실패: "변환하지 못했어요 · old.avi" + 짧은 이유. 재시도는 패널 카드의 "다시".
  - 여러 파일 작업은 마지막 파일이 끝났을 때 한 번만.
- 1초 안에 끝나는 이미지 변환도 토스트는 띄운다.
- toast 페이로드에 변환 결과 종류를 추가(빌더 판단).
- DOM hook 클래스(`card`, `data-id`, `ghost`)는 그대로.

## 설정: 새 "변환" 탭

목업 4번 그대로. 탭 순서: 일반 · 패널 · 단축키 · **변환** · 기록.

- 드래그 변환 켜기/끄기 (`Switch`, 기본 켬).
- 변환 키 (`Segmented`):
  - macOS: `⌥ Option`(기본) · `⌃ Control` · `⇧ Shift`
  - Windows: `Ctrl`(기본) · `Alt` · `Shift`
- Finder 창 접근 (macOS만): 자동화 권한 상태(허용됨 / 묻지 않음 / 거부됨). 거부됨이면 시스템 설정을 여는 버튼.
- **FFmpeg** 섹션, 세 상태:
  1. 설치 안 됨: 크기 안내 + "다운로드".
  2. 다운로드 중: 받은 MB / 전체 MB, 속도, 진행 막대, "취소". 압축 해제·검증 단계도 문구로 표시.
  3. 설치됨: 버전, 크기, 설치일, 위치 + "업데이트 확인", "삭제". 그리고 영상 기본 화질(`Segmented`: 작게 · 보통 · 원본).
  - 설정 창을 닫았다 열어도 진행 중 다운로드 상태가 그대로 보인다(상태는 Rust가 가진다).
- **rhwp** 섹션 (HWP 변환): FFmpeg와 같은 세 상태(설치 안 됨 → 다운로드 중 → 설치됨: 버전·크기·설치일·위치·업데이트 확인·삭제). 약 20MB.
- **LibreOffice** 섹션: 찾음(버전, 위치) / 찾을 수 없음 + "설치 페이지 열기"(libreoffice.org 다운로드 페이지). 탭을 열 때마다 다시 찾는다.
- 새 settings 키: `convert`(on/off), `convert_key`, `video_quality`. 키 이름은 [naming](../../agents/conventions/naming.md) 규칙.

## FFmpeg 다운로드

- rhwp도 같은 방식: `engines/rhwp/`, 출처 `github.com/edwardkim/rhwp/releases`(macos-aarch64, windows-x86_64 제공, `SHA256SUMS.txt` 있음). Windows `rhwp.exe`는 MSVC 런타임(MSVCP140/VCRUNTIME140)이 필요할 수 있음(Filee #248) — 빌더 확인.
- 위치: 앱 데이터 폴더 `engines/ffmpeg/` (`ffmpeg`, `ffprobe`, 버전 메타 JSON).
- 출처(빌더가 확인 후 고정):
  - macOS arm64: 정적 빌드 배포처(예: osxexperts.net / evermeet.cx 계열).
  - Windows x64: BtbN/FFmpeg-Builds GitHub Releases 또는 gyan.dev.
- 받은 파일은 **SHA-256 검증** 후 설치. URL·해시는 코드에 고정하고, "업데이트 확인"은 고정된 최신 항목과 설치 버전 비교.
- macOS: 받은 실행 파일의 quarantine 속성 제거, 실행 권한 부여.
- 업데이트 체크와 같이 네트워크는 사용자가 누를 때만 쓴다(overview의 "네트워크는 업데이트 확인만" 원칙에 FFmpeg 다운로드 추가 → `docs/agents/overview.md` 갱신).

## 리뷰에서 정한 것 (Claude 판단)

- **키를 뗐다 다시 누르면** 그 순간 커서 자리에서 폴더를 다시 찾고 오버레이를 다시 띄운다. 토스트는 한 드래그에 한 번만.
- **변환 드롭은 복사로 치지 않는다**: 조각에 놓든 도넛 밖(오버레이 창 위)에 놓든 `confirm_copy`(클립 맨 위로, 복사 소리, "복사됨" 토스트)를 하지 않는다. 일반 드롭 경로는 그대로.
- **자동화 권한은 드래그 중에 묻지 않는다**: 설정 "Finder 창 접근" 줄에 "권한 요청" 버튼을 둔다. 권한이 아직 정해지지 않았으면 드래그 중 Finder 창은 "폴더 아님"으로 보고, 토스트 문구로 설정을 안내한다. AppleScript 호출은 메인 스레드 밖에서.
- **릴리스 빌드 권한**: `Info.plist`에 `NSAppleEventsUsageDescription`, entitlements에 `com.apple.security.automation.apple-events` 추가(hardened runtime에서 없으면 조용히 실패).
- **커서 아래 창 찾기**는 Vee 자신의 창(오버레이, 고정 패널)과 드래그 이미지 창을 건너뛴다.
- **Windows 11 탐색기 탭**: HWND가 같은 탭이 여럿이므로 보이는 탭(`ShellTabWindowClass`)의 폴더를 고른다.
- **Windows 변환 키 Shift/Alt**: 누른 채 놓을 때 커서 모양이 "이동/링크"로 보일 수 있다. 오버레이 위 드롭은 항상 복사로 받으므로 동작엔 문제 없음. 그래도 보기 이상하면 Windows 선택지는 Ctrl만 남기고 빌더가 보고한다.
- **macOS 이미지 경로**: 디코딩·대부분 포맷은 `sips`가 맡는다. WEBP 출력은 `sips`로 PNG를 만든 뒤 `image` 크레이트로 쓴다(무손실 WEBP). `image` 기능 플래그 추가가 필요하면 의존성 변경으로 보고 사용자 확인.
- **FFmpeg macOS 출처**: Apple Silicon 빌드(osxexperts 계열). evermeet.cx는 Intel 전용이라 제외.
- **1단계 첫 작업은 Windows 스파이크**: Windows는 `DoDragDrop`이 메인 스레드에서 모달 루프를 도는데, 그동안 `convert` 창 표시·이동·이벤트·드롭 수신이 되는지 먼저 확인한다. 안 되면 vendored `drag`에서 드래그를 별도 STA 스레드로 옮기는 패치(`VEE_PATCH.md`에 기록).

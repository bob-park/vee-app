## 왜

사용자는 kiri-app의 **애니메이션과 UI/UX**가 좋았고, Vee 전체를 그 느낌으로 다시 디자인하길 원한다. 두 앱은 같은 Kraken 보라 팔레트와 같은 스택(Tauri 2, React 19, Tailwind 4, daisyUI 5, 애니메이션 라이브러리 없음)을 쓰므로, kiri의 "Aurora Glass" 언어(오로라 블롭 + 유리 카드 + 하나의 스프링 곡선)를 Vee의 다섯 창에 옮긴다.

## 사용자가 정한 것

1. 새 브랜치에서 작업한다.
2. **전체 방향**: kiri처럼 오로라 + 유리 카드. 단, Vee는 다른 앱 위에 뜨는 창이 많으므로 **"은은한 오로라"**: 창 바탕은 단색, 오로라는 상단(툴바/탭 바) 뒤에만 빛처럼 번진다. 오로라가 창 전체를 채우는 kiri 방식(설정 A안)은 고르지 않았다.
3. **패널 (⌘V)**
   - 바탕 단색 + 툴바 뒤 오로라. 검색창·필터·아이콘 버튼은 유리.
   - 모든 카드는 같은 크기의 유리 카드. 머리줄(앱 이름 · 타입 배지 · 시간) 아래에 **내용 타일**이 들어간다. 텍스트·코드·링크도 이미지처럼 타일 안에 담긴다.
     - 텍스트: 타일 + 구석에 옅은 큰따옴표 장식.
     - 코드(지금 코드로 보이는 텍스트를 구분한다면): 고정폭 글꼴 타일.
     - 링크: 타일 위 절반은 그라데이션 + 큰 🔗(체인) 아이콘, 아래에 굵은 도메인 + URL 한 줄. **URL·도메인이 길면 `…`로 자른다.** 링크 카드 크기는 다른 카드와 같다.
     - 이미지·파일: 지금처럼 썸네일/아이콘을 타일에.
   - **지금 카드의 나머지 요소는 모두 그대로 살린다**(사용자 확정). 카드는 위에서부터 **머리줄 → 내용 타일 → 아래 줄** 순서로 쌓이고, 그만큼 타일은 목업보다 낮아진다. 링크 타일의 "위 그라데이션 + 아래 도메인/URL" 배치도 이 높이에 맞춘다.
     - 아래 줄(footer): 글자 수 / 이미지 크기 / 「이름 외 N개 파일」, `missing` 빨간 경고, 선택된 카드의 복사 안내, 변환 후 저장 폴더.
     - 왼쪽 위에 옅게 깔린 출처 앱 아이콘(워터마크).
     - hover 시 나오는 📌 버튼.
     - 고정 / 변환 실패 / 변환 완료 테두리 색, 삭제 확인 오버레이, 변환 진행 표시.
   - 고정 카드 뒤 세로 구분선은 지금처럼 유지. 고정 카드도 시간 자리에 시간을 보여준다(목업의 「고정」 글자는 목업에만 있던 것).
   - 움직임: 패널이 스프링으로 올라옴, 카드는 흐릿→선명(deblur)하며 순서대로 들어옴, 새 카드는 보라 링 한 번, 필터 선택 표시는 미끄러지는 알약, 카드 hover 시 살짝 떠오름.
   - *(Claude 판단)* 카드 등장 stagger는 짧게 하고, 패널이 열리는 즉시 키보드 선택·복사가 되어야 한다(애니메이션이 입력을 막지 않음).
4. **설정**: 배경 단색 + 탭 바 뒤 오로라. 가운데 유리 탭 바(6개 탭) + 미끄러지는 선택 알약, 섹션은 유리 카드이고 탭을 바꾸면 차례로 들어옴. 테마는 kiri처럼 **미니 미리보기 카드**(시스템은 대각선 반반), 언어 등 Segmented는 미끄러지는 알약, Switch는 스프링 썸.
5. **토스트**: 단색 카드 + 옅은 오로라 빛, 아이콘은 유리 타일, 아래에서 흐릿→선명하게 올라옴, ✓ 배지가 pop + 초록 링.
6. **변환 도넛**
   - 모양: **말랑한 링** — 도넛 조각 6개(포맷 수만큼)가 네 모서리가 둥근 채로 간격을 두고 놓인다. 조각끼리 겹쳐 보이면 안 된다.
   - **가운데 파일 이름은 없앤다.** 살짝 흔들리는 ↓ 아이콘 + 짧은 드롭 안내만.
   - **받침 원판**: 도넛 뒤에 단색 원판(안에 은은한 오로라, 얇은 테두리, 그림자). 흰 배경/흰 Finder, 검은 배경 어디서도 보여야 한다.
   - **다크 모드 대비(③안)**: 원판 바깥으로 보라·하늘·분홍 후광이 약하게 돈다 + 조각을 바탕보다 한 톤 밝게, 위쪽에 1px 빛 테두리.
   - 원판이 튀어나오고 조각이 회전하며 차례로 펼쳐짐, hover 조각은 보라로 채워지며 커짐.
7. **새 기능 안내**: 설정과 같은 상단 오로라, 버전 배지 pop, 제목·항목 카드가 차례로 들어옴, 확인 버튼은 보라→하늘 그라데이션.
8. **폰트**: Pretendard로 바꾼다. kiri처럼 npm `pretendard` 패키지를 **의존성으로 추가하는 것을 사용자가 승인했다**(kiri는 1.3.9).
9. **링크 실제 미리보기(OG 이미지·제목 가져오기)는 이번 범위 밖.** 네트워크 요청·새 Rust 의존성·개인정보(토큰 달린 URL 자동 접속) 문제가 있어 별도 기능으로 한다.

## 목표

- 다섯 창이 하나의 디자인 언어(단색 바탕 + 은은한 오로라 + 유리 요소 + 하나의 스프링 곡선)로 보인다.
- 사용자가 고른 목업과 같은 느낌이 라이트/다크, 한국어/English에서 모두 난다.
- 투명 창(패널·토스트·도넛)이 흰 배경·검은 배경·일반 배경화면 위 어디서도 또렷하다.

## 비목표

- 기능·동작 변경. 패널 크기 조절, 고정, 드래그(기울기·ghost), FLIP 재정렬, 변환 진행 표시, 토스트 표시 시간·위치, 단축키, 창 크기 저장 등은 **그대로**. 바뀌는 건 겉모습과 움직임의 질감뿐.
- 링크 실제 미리보기 (위 9).
- macOS 네이티브 vibrancy/블러. 유리는 kiri처럼 CSS(`backdrop-filter`)만으로, 앱 내부 요소 위에서만 쓴다.
- 애니메이션 라이브러리 추가. kiri처럼 CSS keyframes + 기존 WAAPI(`motion.ts`)로 한다.

## 반(反)목표 — 기술적으로 돌아가도 실패인 것

- 다른 앱 위에 뜨는 패널이 시끄러워서 카드 내용이 읽기 어려워짐.
- 투명 창이 흰/검은 배경에서 사라져 보임.
- 움직임 줄이기(`prefers-reduced-motion`)를 켰는데 애니메이션이 남아 있음.
- 창마다 다른 이징·다른 유리 레시피가 섞임.
- 패널 열고 닫기, 드래그가 지금보다 느리거나 버벅임.

## 제약

- 프로젝트 규칙을 따른다: `docs/agents/design.md`(색은 `globals.css`에만, 컴포넌트에 hex/rgb 금지, 새 토큰은 라이트·다크 값 둘 다, 기존 DOM hook 클래스 `.card` + `data-id`, `.update`, `.ghost` 유지, ARIA 역할·`:focus-visible` 유지), i18n(모든 문구는 `src/shared/i18n/{en,ko}.ts`), react-sections, tailwind-daisyui.
- **`docs/design/`이 디자인의 기준이다.** 지금은 `kraken-design.md`뿐이다. 이번 작업에서 kiri의 `aurora-glass.md`를 참고해 Vee용 디자인 문서(팔레트, 유리, 오로라, 모션 표, 창별 레이아웃)를 `docs/design/`에 쓰고, `docs/agents/design.md`의 "리팩터는 픽셀 동일" 규칙이 이번 리디자인과 충돌하지 않도록 기준 문서를 갱신한다.
- 애니메이션 시간이 Rust와 맞물린 곳이 있다: 토스트 퇴장 `TOAST_EXIT_MS`, 패널 닫힘 `PANEL_CLOSE_MS=200`(`src-tauri/src/app/window.rs`). 시간을 바꾸면 양쪽을 같이 바꾼다.
- 창 크기: 패널 1200x300(높이는 화면 비율), 토스트 420x132, 도넛 260x260, 설정 520x600, 새 기능 안내 400x480. 도넛의 후광·그림자가 창 밖으로 잘리지 않게 해야 한다(원판을 줄이든 창을 키우든 빌더 판단).
- 의존성 추가는 `pretendard` 하나만 승인됨. 그 외 추가는 사용자에게 먼저 묻는다.
- 완료 전: `cargo test --manifest-path src-tauri/Cargo.toml --lib`, `yarn test`, `yarn typecheck`, `yarn lint` 통과 + `yarn tauri dev`로 다섯 창을 라이트/다크 × 한국어/English로 직접 확인.

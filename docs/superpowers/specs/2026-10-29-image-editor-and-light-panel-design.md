## 1. 라이트·다크 패널이 배경 위에서 잘 보이게

### 왜

흰 웹페이지 위에 패널을 띄우면 경계가 안 보인다. 패널 바탕 `#f6f5fb`가 흰색과 거의 같고, 테두리 `#dedee5`는 옅고, 바깥 그림자가 없다(패널 창이 패널과 크기가 같아서 바깥 그림자는 잘린다). 카드의 출처 앱 아이콘도 16% 워터마크라 무슨 앱인지 안 보인다.

### 정한 것 (사용자)

- **경계: 시안 B. 패널 바탕을 한 톤 내린다.** 라이트는 흰 페이지와 구분되는 옅은 회보라(시안 값 `#eeedf6`, 테두리 `#d3d2df` 정도). 테두리 굵기·그림자는 그대로.
- **앱 아이콘: 시안 B. 지금 워터마크 모양(위치·크기·마스크) 그대로, 투명도만 올린다.** 라이트 16% → 약 45%.
- **다크도 같이 맞춘다.** 어두운 웹페이지 위에서도 경계가 보이게 패널 바탕을 한 톤 올리고, 워터마크 투명도도 비슷한 비율로 올린다.

### 제약

- 색은 `src/app/globals.css`에만, 두 테마 모두. 패널 바탕은 지금 `bg-base-100`이다. `base-100`을 바꾸면 설정·새 기능 안내 창 바탕도 바뀌므로, **패널 전용 토큰**(`--vee-panel` → `bg-panel` 같은 이름)을 새로 두는 쪽이 안전하다(빌더 판단, 아래 참고).
- 유리 카드(`.glass`)는 새 바탕 위에서 오히려 더 또렷해진다. 유리 레시피 자체는 바꾸지 않는다.
- 확인: 흰 페이지 / 검은 페이지 위에서 라이트·다크 모두.

## 2. 설정 화면 그림이 macOS Sonoma에서 쪼그라듦

### 증상

macOS 27 미만(사용자는 **Sonoma, macOS 14**에서 확인)에서 설정 › 일반의 테마 미리보기(`ThemePicker`)와 패널 위치 그림(`PositionPicker`)이 너무 작아져 안 보인다. macOS 27에서는 정상.

### 추정 원인 (확인 필요)

두 컨트롤 모두 `Row`(가로 flex, `justify-between`) 오른쪽에 들어가고 자기 너비를 고정하지 않는다. `ThemePicker`는 `flex gap-2` 안에 `w-[74px]` 버튼, `PositionPicker`는 너비 없는 `grid grid-cols-4`. 예전 WebKit(Safari 17)은 버튼/그리드의 min-content 계산과 flex 축소가 달라 라벨 쪽에 공간을 빼앗기는 것으로 보인다. 구현 시 `superpowers:systematic-debugging`으로 원인을 확정한다.

### 목표

macOS 27에서 보이는 크기와 같게. Sonoma 기기가 없으면 **어떤 WebKit에서도 줄지 않게 크기를 명시**한다(예: 그림 쪽 `shrink-0`, 그리드/타일의 명시적 너비). macOS 27에서 픽셀이 바뀌면 안 된다.

## 3. 이미지 편집 창

### 왜

스크린샷에서 필요한 부분만 잘라 바로 붙여넣고 싶다. 같은 창에서 회전·크기 조절, 그리고 제품 사진 배경 제거, 흐릿한 스크린샷 글자를 또렷하게 하는 화질 개선까지.

### 흐름

1. 패널에서 이미지 카드를 끌면 변환 도넛이 뜬다. 도넛에 **"편집" 조각**을 하나 추가한다(이미지 카드일 때만).
2. 그 조각에 놓으면 **새 편집 창**(여섯 번째 창)이 열린다.
3. 탭을 오가며 편집을 쌓는다(자르고 → 돌리고 → 크기 바꾸고 …).
4. **복사**를 누르면 결과 PNG가 클립보드에 들어가 바로 붙여넣을 수 있고, **히스토리에도 새 항목**으로 남는다. 원본 항목은 그대로. 창은 닫힌다.
5. **취소**는 아무것도 남기지 않고 닫는다.

대상은 이미지 한 장인 카드. 여러 장이 묶인 카드는 편집 조각을 보이지 않는다(제 판단).

### 화면 (시안 `editor-layout.html`의 A)

- 위: 오로라 + 유리 Segmented 탭 **자르기 / 회전 / 크기 / 배경 제거 / 화질 개선**.
- 가운데: 이미지 캔버스.
- 아래 막대: 왼쪽에 크기 정보(`1280 × 720 → 612 × 344`), 오른쪽에 **취소** / **복사**(보라→하늘 그라데이션 `from-primary to-sky`).

#### 자르기

- 이미지 위에서 드래그로 영역을 잡고, 모서리·변 핸들로 조절. 영역 밖은 어둡게.

#### 회전 (시안 `rotate-icons.html` B + `rotate-icons-v2.html` 3)

- 이미지 아래에 버튼 두 개: **투톤 아이콘 + "-90°"**, **투톤 아이콘 + "+90°"**.
- 투톤 아이콘 = 둥근 사각형(옅은 primary 채움 + 1.7px 선) 위로 넘어가는 화살표. 좌/우 대칭. SVG로 직접 그려 공용 아이콘 위치에 둔다. 색은 `currentColor`/토큰.
- 자유 각도 회전은 없다.

#### 크기

- **너비·높이 숫자 입력 폼**(px). 기본은 비율 유지, 잠금 토글로 해제.

#### 배경 제거 (시안 `bg-remove.html` B)

- 탭에 들어가면 처리하고, **diff 막대**로 원본(왼쪽) ↔ 결과(오른쪽, 투명 부분은 체크무늬)를 비교한다.
- 결과는 투명 배경 PNG.

#### 화질 개선 (시안 `upscale-diff.html` B)

- 목적: 작고 흐릿한 스크린샷의 **글자를 또렷하게**.
- **2배 / 4배** 선택(기본 2배, 제 판단). 결과 긴 변이 4096px를 넘으면 4096px로 맞춰 줄인다(제 판단).
- **diff 막대**로 원본 ↔ 개선본 비교 + **맞춤 / 100%** 보기 전환. 100%에서는 끌어서 이동하고, 오른쪽 아래 작은 지도에 현재 위치를 보여 준다.
- 아래 줄에 `420 × 180 → 840 × 360`처럼 결과 크기.

#### 공통

- 비교 막대는 **daisyUI `diff`** 컴포넌트를 쓴다. 지금 `globals.css`의 daisyUI `exclude`에 `diff`가 있으므로 그것만 뺀다. 색·테두리는 Vee 토큰으로 맞춘다.
- AI 처리 중에는 진행 표시, 그동안 다른 탭과 복사는 잠긴다.
- 모델이 없으면 그 탭에 "설정에서 모델 받기" 안내 + 설정 › 변환으로 가는 버튼(도넛의 `needs` 안내와 같은 결).
- 모든 문구는 `src/shared/i18n/{en,ko}.ts`.

### AI 모델과 다운로드

- 배경 제거·화질 개선 모두 **로컬 AI 모델**을 쓴다. 이미지는 기기 밖으로 나가지 않는다.
- **macOS와 Windows 모두 모델을 내려받는다**(결과를 같게 하려고. macOS 내장 Vision 배경 제거는 쓰지 않는다 — 사용자 결정).
- 다운로드는 설정 › 변환 탭에서. 기존 `EngineSection`(FFmpeg / rhwp: 크기 표시, 다운로드·진행·취소, 업데이트, 삭제, sha256 검증, `<app data>/engines/<name>/`)을 그대로 재사용해 모델 두 개를 항목으로 추가한다.
- 주 사용 이미지: 스크린샷, 제품 사진. 모델은 이 두 가지에 맞는 것으로 고른다.
- **실행: Rust `ort`(ONNX Runtime) 크레이트를 추가한다 — 사용자 승인.** ONNX Runtime 라이브러리(약 20–30MB)는 앱 번들에 넣지 않고 모델과 함께 엔진으로 내려받아 동적으로 불러온다(제 판단). 배경 제거·화질 개선 모두 같은 런타임을 쓴다.
- 지금 엔진 다운로더는 실행 파일(`Raw`/`Archive`)만 알고, 최신 버전을 GitHub에서 찾고, 허용 호스트 목록이 있다. 모델·런타임 파일을 받을 수 있게 넓힌다(새 `AssetKind`, Hugging Face 등 호스트 추가, 버전은 우리가 고정한 모델 리비전 + sha256로 판단).
- **모델 라이선스: 상업적 사용이 허용된 것(MIT/Apache 등)만** (제 판단, Vee는 MIT 배포). RMBG-1.4/2.0 같은 비상업 모델은 쓰지 않는다. 그 안에서 스크린샷·제품 사진 품질과 크기를 보고 고른다.
- **화질 개선 모델이 기준에 못 미치면** (스크린샷에서 글자를 뭉개거나 다른 글자로 바꿈): **AI 대신 Lanczos 확대 + 선명화로 같은 탭을 제공한다 — 사용자 결정.** 이 경우 화질 개선용 모델 다운로드 항목은 없다.
- **AI 단계의 의미** (제 판단): 배경 제거·화질 개선은 그 시점까지 편집된 이미지(자르고 돌린 결과)에 적용된다. 앞 단계가 바뀌면 다시 처리하고, 같은 입력이면 결과를 캐시해 재사용한다.
- **히스토리 새 항목:** 앱이 스스로 쓴 클립보드는 watcher가 무시한다(`suppress_until`, `src-tauri/src/app/state.rs`). 그래서 복사할 때 새 항목을 직접 넣고, 기존 변경 이벤트로 패널을 갱신한다.

### 비목표

- 자유 각도 회전, 필터·색 보정, 그리기/주석, 여러 장 일괄 편집.

- 클라우드 처리.

### 실패로 볼 것 (돌아가도 안 됨)

- 원본 히스토리 항목이 바뀌거나 사라짐.
- 화질 개선이 글자를 오히려 뭉개거나 다른 글자처럼 바꿈(스크린샷 기준으로 확인).
- 라이트/다크, 한국어/English 중 하나라도 깨짐.

### 제약

- 새 창·커맨드·이벤트는 `docs/agents/` 규칙(tauri-commands, rust-modules, react-query 다중 창 동기화, react-sections, naming)을 따른다. 새 히스토리 항목이 패널에 바로 보여야 한다.
- 의존성 추가·변경은 사용자 확인 후에만(CLAUDE.md). `ort`는 승인됨. 그 밖의 새 의존성은 다시 묻는다.
- 검증: `cargo test --manifest-path src-tauri/Cargo.toml --lib`, `yarn test`, `yarn typecheck`, `yarn lint`, 그리고 `yarn tauri dev`로 라이트/다크 · ko/en 확인.

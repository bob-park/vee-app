# 캡처·녹화 모션 다듬기 + macOS 커서 즉시 갱신

## 의도

스크린 캡처와 스크린 녹화 흐름 전체가 끊김 없이 부드럽게 보이게 한다. 그리고 macOS에서 Space(또는 툴바)로 "영역"↔"창"을 바꾸면 마우스를 움직이기 전에도 커서 아이콘이 바로 바뀌게 한다.

## 목표

- 창 모드 하이라이트(보라 tint, 구멍, 녹화 점선)가 창에서 창으로 미끄러지듯 따라간다.
- 영역↔창 전환, 캡처 완료, 녹화 시작/종료, 녹화 pill의 등장과 퇴장이 모두 페이드나 이동으로 이어지고, 툭 끊기는 순간이 없다.
- 타이밍과 곡선은 `docs/design/aurora-glass.md` 모션 표를 따른다(등장 `ease-spring`, 퇴장 150–250ms `ease-in`, 이동 `EASE_MOVE`).
- macOS에서 모드를 바꾸거나 오버레이가 열리면 커서가 즉시 바뀐다.

## 비목표와 반목표

- 비목표: 새 애니메이션 라이브러리, 레이아웃이나 시각 디자인 변경, Windows 커서 동작 변경.
- 반목표: 애니메이션 때문에 캡처가 늦어지거나, 촬영 이미지에 오버레이가 찍히거나, 드래그 선택이 마우스보다 뒤처지는 것. 드래그 중인 사각형은 지금처럼 마우스에 바로 붙어 있어야 한다.

## 제약

- `prefers-reduced-motion`이면 모든 새 모션이 꺼지고 최종 상태가 바로 보인다(`motion.ts`의 `reducedMotion()` 재사용).
- 의존성은 추가하지 않는다.
- Rust 쪽 숨김 타이밍(`FADE_MS`, `CROSSFADE_MS` 등)과 CSS duration을 맞물려 둔다.

## 방법 (검토한 것)

- A. CSS만 다듬기: 가장 작지만, SVG 도형의 위치·크기 전환은 WebKit이 CSS로 지원하지 않아 하이라이트 순간이동이 남는다.
- **B. A + `requestAnimationFrame` 기반 작은 tween 훅 (선택)**: 하이라이트 사각형 좌표를 `EASE_MOVE`로 보간한다. 라이브러리가 필요 없다.
- C. Motion 같은 라이브러리: 범위에 비해 과하고 의존성이 늘어나서 제외했다.

사용자가 B를 골랐다.

## 결정된 것

- **tween 훅**: `Rect | null` 목표를 받아 표시용 `Rect`를 돌려준다. 목표가 바뀌면 현재 표시 위치에서 새 목표로 약 180ms 동안 `EASE_MOVE`로 보간한다. 처음 나타날 때(null→rect)는 이동 없이 그 자리에서 페이드 인한다. reduced-motion이면 보간하지 않는다. 창 hover tint, 그 tint의 `covered` 마스크 기준, 녹화 대기 점선(`planned`), 창 선택 구멍(`hole`)에 적용하고, 드래그 중인 사각형에는 적용하지 않는다.
- **커서 (macOS)**: 오버레이가 모드를 바꾸거나 열린 직후, Rust가 현재 커서 위치에 `mouseMoved` CGEvent를 한 번 post해서 WKWebView가 커서를 다시 계산하게 한다. 모드 이벤트를 받을 때 프론트엔드가 Rust 커맨드를 부르거나, Rust가 이미 처리하는 경로에 붙인다.

## 빌더에게 맡기는 것

- 실제 앱(`yarn tauri dev`)에서 흐름을 따라가며 끊기는 곳을 확인하고, 그 목록에 맞춰 손볼 곳을 확정한다. 코드에서 찾은 후보는 영역↔창 전환 시 구멍과 강조, 캡처 완료 시 즉시 사라짐, 녹화 pill 퇴장, 녹화 테두리 fade의 곡선이다.
- 캡처 완료 페이드는 촬영보다 늦게 시작해야 오버레이가 찍히지 않는다. 지금 `take_capture`가 창을 언제 숨기는지에 맞춰 정한다.
- 커서 갱신 커맨드의 위치와 이름은 `tauri-commands`, `rust-modules` 규칙을 따른다.
- tween 훅은 작은 순수 보간 함수와 그 함수의 `node:test` 하나를 함께 둔다.
- 검증: 라이트/다크, 한국어/English, 그리고 4가지 검사(cargo test, yarn test, typecheck, lint).

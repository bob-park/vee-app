# PDF → Markdown Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Dragging a PDF file card onto the convert donut offers one `MD` slice that writes `<stem>.md` (page-by-page plain text for AI input) into the folder under the cursor.

**Architecture:** PDFium (`bblanchon/pdfium-binaries` `chromium/8125`) is fetched at build time and bundled like ONNX Runtime (macOS `Contents/Frameworks`, Windows beside the exe). The app never loads it: each PDF is converted by a one-shot child `vee-app --pdf-worker <lib> <src> <out>` run through the existing `process::exec` (timeout, cancel, kill on drop). PDFs get their own branch in `formats_for`/`run`, like videos, so no new `Engine` variant and no engine UI.

**Tech Stack:** Rust (Tauri 2), `pdfium-render` 0.9.5 (approved), Node fetch script, React/TS (one union member).

**Spec:** `docs/superpowers/specs/2026-11-02-pdf-to-md-design.md`

## Global Constraints

- PDFium release pinned to `chromium/8125`; assets `pdfium-mac-arm64.tgz` (`lib/libpdfium.dylib`) and `pdfium-win-x64.tgz` (`bin/pdfium.dll`); archive + library SHA-256 pinned (measured at pin time).
- `pdfium-render = { version = "0.9.5", default-features = false, features = ["pdfium_8125"] }`. No other new direct dependency without asking the user.
- No `disable-library-validation`; the dylib is signed with the app via `bundle.macOS.frameworks`.
- The app process never loads PDFium; only the `--pdf-worker` child does.
- An all-empty PDF (scanned) is a failure (`JobError::Engine`), never an empty `.md`. No new `JobError`, no new i18n strings.
- Output: UTF-8, no BOM, `\n` line endings, `# <stem>` then `## Page N` per page.
- Cancel button stays video-only (`cancellable` rule unchanged).
- Worker timeout 120 s.
- Identifiers/comments/docs/agents in English; conventions in `docs/agents/conventions/`.
- **Deviation from spec §4 (allowed by "builder may find smaller"):** no `Engine::Pdfium`; PDFs are a separate branch like videos. Update the spec line in Task 5.

## Review Focus

- `.PDF` / `.Pdf` upper-case extension → still offers `MD` (test in Task 2).
- Corrupt or password-protected PDF → job fails with the normal failure toast; Vee keeps running (worker exits non-zero; test in Task 3 on a non-PDF file renamed `.pdf`).
- `a.md` already exists in the target folder → writes `a (1).md`, never overwrites (existing `unique_path`; covered by `run` going through it — assert in Task 3 integration test).
- PDF mixed with a `.docx` or an image in one drag → empty donut (test in Task 2).
- Korean file name / Korean text → title and body survive byte-for-byte (golden fixture in Task 3).

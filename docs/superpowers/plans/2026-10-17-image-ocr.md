# Image OCR Search Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Text inside image clips and image files in files clips is recognized by the OS OCR and found by the existing search box.

**Architecture:** Migration `0006` adds `clips.ocr_text` (`NULL` = pending, `''` = done/nothing) and rebuilds `clips_fts` over `(text, ocr_text)`. A single background worker thread picks the newest pending image/files clip, runs `app::ocr::recognize` per image without holding the DB lock, and writes the result; the watcher and the `ocr` setting wake it. Backfill of old clips is the same loop.

**Tech Stack:** Rust (rusqlite FTS5 trigram, `objc2-vision` 0.3.2 on macOS, `windows` 0.62 WinRT `Media_Ocr` on Windows), React settings UI.

**Spec:** `docs/superpowers/specs/2026-10-17-image-ocr-design.md`

## Global Constraints

- Branch `feature/image-ocr`. Commit messages `<prefix>(<scope>): <subject>` ([commit-messages](../../agents/workflow/commit-messages.md)).
- Dependencies (approved 2026-10-17): macOS `objc2-vision = "0.3.2"` (enable only the features used); Windows add only the needed `windows` 0.62.2 features (`Media_Ocr`, `Graphics_Imaging`, `Storage`, `Storage_Streams`, `Foundation`, `Foundation_Collections`, `Globalization` as required). No other dependency changes.
- Never edit migrations `0001`–`0005` or `legacy_schema` in `shared/db.rs`. New schema must stay readable by older builds (add only).
- macOS Vision: `recognitionLevel = accurate`, `recognitionLanguages = ["ko-KR", "en-US"]`.
- Image files: extension per `watcher::is_image_path`, existing regular file, ≤ 50MB (`MAX_IMAGE_BYTES`). Files clips: **all** such files, no count limit.
- Setting key `ocr`, values `on`/`off`, default `on`. Off: no new OCR, existing `ocr_text` still searchable. Off→on: wake the worker.
- OCR engine unavailable → write nothing, stop the worker for this run (pending stays `NULL`, retried next launch).
- OCR never blocks clip capture; the DB mutex is never held during recognition.
- User-visible strings only in `src/shared/i18n/{en,ko}.ts`. Code and comments in English.
- Done = `cargo test --manifest-path src-tauri/Cargo.toml --lib`, `yarn test`, `yarn typecheck`, `yarn lint` all pass.

## Review Focus

- A clip deleted (or pruned by retention) while its OCR runs → the result write is a silent no-op. Test in Task 1.
- The same image copied again (upsert bumps the existing row) → its `ocr_text` is kept, not reset to pending. Test in Task 1.
- An older build reinstalled over a v6 DB inserts text clips with `ocr_text = NULL` → the worker must ignore them (kind filter). Test in Task 1.
- A corrupt or non-image file with an image extension → `recognize` returns `Ok("")`, no panic, clip marked done. Test in Task 2.
- User turns OCR off mid-backfill → the worker stops after the current image and does nothing until turned on. Test in Task 3 (`worker_step` returns without work when off).

### Task 3: Background worker, `ocr` setting (Rust), wiring

**Files:**
- Modify: `src-tauri/src/app/ocr/mod.rs` (worker), `src-tauri/src/domain/settings/mod.rs` (default `"ocr" => "on"`, validate `on|off`), `src-tauri/src/domain/settings/model.rs` + `commands.rs` (`SettingsDto.ocr: String`; `set_setting` calls `ocr::wake()` when `key == "ocr"`), `src-tauri/src/app/watcher.rs` (call `ocr::wake()` after a successful `capture`; make `MAX_IMAGE_BYTES` `pub(crate)`), `src-tauri/src/lib.rs` (`ocr::spawn(app.handle().clone())` after `watcher::spawn`)

**Interfaces:**
- Consumes: Task 1 `next_ocr_pending`, `set_ocr_text`; Task 2 `recognize`, `Unavailable`; `settings::get(conn, "ocr")`.
- Produces: `pub fn spawn(app: AppHandle)`, `pub fn wake()` (no-op before spawn; sender kept in a `OnceLock<Mutex<Sender<()>>>` or equivalent).
- Produces (testable core): `enum Step { Idle, Done, Stop }` and `fn worker_step(db: &Mutex<Connection>, recognize: impl Fn(&Path) -> Result<String, Unavailable>) -> AppResult<Step>`:
  - lock → if `settings::get(conn, "ocr") != "on"` → `Idle`; `next_ocr_pending` → `None` → `Idle`; unlock.
  - paths: `Image(p)` → `[p]`; `Files(lines)` → lines filtered by `is_image_path`, existing file, ≤ `MAX_IMAGE_BYTES`.
  - recognize each without the lock, with the same short pause between files; any `Err(Unavailable)` → `Stop` (write nothing). Join non-empty results with `\n`; lock; `set_ocr_text`; `Done`. Files clip with no image paths → `set_ocr_text(id, "")`, `Done` without calling `recognize`.
- Loop in `spawn`'s thread: `Done` → sleep a short pause (e.g. 200ms) then continue; `Idle` → block on the wake channel; `Stop` → log once and return; `Err` → log, wait for wake.
